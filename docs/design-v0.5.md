# 통역 앱 v0.5 · 독립 웹/PWA와 선택적 현장 운영

- 기준일: 2026-09-05
- 상태: 구현 기준 설계. 미검증 항목은 해당 기능의 출시 조건으로 명시한다.
- 범위: 순차통역·동시통역·설정·기록. 대화형 비서 탭은 제외한다.
- 기본 구조: 스마트폰 → Gemini 직접 연결. 운영자가 상시 켜 두는 서버는 없다.
- 비용 정책: 무료 티어와 기존 인프라만 사용한다. 유료 자동 전환은 구현하지 않는다.
- 이 문서는 v0.4를 대체한다. 기존 `interp-web`은 선택적 현장 허브로 유지한다.

## 1. 취지와 변경하지 않는 결정

1. 자비스 오브의 통역 창을 완전히 독립된 앱으로 만든다. 스마트폰에서 사용할 수 있고, 개인 맥이나 오브 설치를 요구하지 않는다.
2. 운영자의 맥·VM·중계 서버를 상시 켜 두지 않는다.
3. 사용자는 자기 Google 계정의 Gemini API 키를 설정한다. 사용량과 비용 책임은 해당 사용자에게 있다.
4. 키가 없는 사용자는 관리자가 제공하는 공용 키를 현장에서 임시로 사용한다. 개인 키는 장소 제한 없이 사용한다.
5. 한국어·영어·일본어 UI를 첫 공개 버전부터 제공한다.
6. 설치 없이 웹에서 시작한다. PWA 설치와 Android APK 다운로드로 확장한다.
7. 새 유료 구독·종량제 API를 도입하지 않는다. 스토어 관련 유료 항목은 오너 승인 대상으로 남긴다.
8. 주요 사용처는 설교 청취, 1:1 대면 통역, 전화 통역 보조, 여행 회화다.

**구현상 반드시 구분할 것:** “상시 서버 없음”은 자체 백엔드를 운영하지 않는다는 뜻이다. 정적 호스팅과 Google 서비스, 인터넷 연결은 필요하다.

또한 “공간 한정”이라는 요구는 유지하지만, 공인 IP 제한으로 증명할 수 있는 것은 **허용된 행사장 회선을 통한 API 접근**이다. 물리적 위치를 완벽하게 증명하는 기능으로 설명하거나 출시해서는 안 된다. 이 차이의 처리 방안은 §5와 §18에 명시한다.

## 2. 사실·설계값·미검증 항목의 구분

### 2.1 설계 입력으로 확정된 사실

아래는 오너가 제공한 실측·확인 결과이며, 본 설계에서 다시 추정하지 않는다.

| 항목 | 확인된 결과 |
|---|---|
| 순차 번역 | `gemini-3.1-flash-lite`, thinking 0 → `gemini-3.5-flash` 캐스케이드, 약 1초 |
| 출력 검증 | 출력 언어 검증 후 폴백 |
| Live 목소리 | `gemini-3.1-flash-live-preview`, 텍스트를 읽도록 지시 → PCM16 24kHz 스트림 |
| Live 목소리 지연 | 첫소리 0.55~0.73초 |
| Live 목소리 선택 | 프리빌트 보이스 30종 |
| 동시통역 | `gemini-3.5-live-translate-preview` → `gemini-3.1-flash-live-preview` 폴백 |
| 동시통역 입력·출력 | 마이크 PCM16 16kHz 입력, 24kHz 오디오와 `outputTranscription` 출력 |
| 번역 전용 Live 모델 | `translationConfig` 사용, 시스템 프롬프트 불가 |
| TTS API | 3.1 TTS 무료 하루 10회·분당 3회, 503 잦음. 2.5 TTS는 비스트리밍 9~14초 |
| 브라우저 연결 | Gemini REST와 Live WebSocket 직접 호출 가능 |
| 키 제한 | 애플리케이션 제한 한 종류와 API 제한을 함께 설정 가능 |
| iOS PWA 마이크 | 실제 지원 상태 미검증 |
| 재사용 자산 | 번역 프롬프트·캐스케이드, Live 클라이언트, SegmentAssembler, PCM 재생기, xlsx 작성기, 현장 허브 |

이 지연 수치는 기존 환경의 결과다. 스마트폰 전체 경로의 성능 보장으로 확대하지 않는다.

Live 목소리에 하루 요청 횟수 제한이 관측되지 않았다는 사실도 무제한 사용을 뜻하지 않는다. 세션·토큰·동시 연결 및 프로젝트 제한은 남는다.

### 2.2 이 문서의 표현 규칙

- **확인됨:** 위 실측 또는 명시한 공식 자료로 확인한 내용.
- **설계값:** 구현자가 적용할 초기 정책. API가 요구하는 고정값이 아니다.
- **미검증:** 실기기·실키 시험 전까지 지원을 보장하지 않는 내용.
- **추정:** 용량·성능 계산이나 예상 결과.

## 3. v0.4 비판과 v0.5 수정 결정

| # | v0.4의 문제 | v0.5 결정 |
|---|---|---|
| 1 | 공인 IP를 물리적 장소와 동일시한다. | “행사장 회선 제한”을 정확한 보안 경계로 정의한다. |
| 2 | 제한 키가 REST에서 거부되면 Live에도 같은 보장이 있다고 가정한다. | REST, Live 신규 연결, 연결 중 네트워크 이동을 각각 실키로 검증한다. |
| 3 | Wi-Fi를 벗어나면 이미 열린 Live도 즉시 차단된다고 읽힌다. | 기존 연결의 제한 재평가 시점은 미검증이다. 즉시 차단을 약속하지 않는다. |
| 4 | VPN·프록시·원격제어·공유 NAT 우회가 없다. | 허용 회선을 원격으로 이용하는 경우와 동일 공인 IP 공유를 위협 모델에 포함한다. |
| 5 | IP 확인 사이트 한 번으로 행사장 출구를 확정한다. | IPv4·IPv6·이중 회선·VPN 등 실제 Google 요청 경로를 검증한다. |
| 6 | `expiresAt`을 붙인 원본 API 키를 만료 키처럼 설명한다. | 앱의 만료 표시는 이용 정책일 뿐이다. 원본 키 폐기와 구분한다. |
| 7 | 방을 닫으면 배포한 키가 회수된다고 설명한다. | 방 폐쇄는 추가 배포 중단이다. 이미 복사된 키는 콘솔에서 폐기해야 한다. |
| 8 | 429 발생 시 항상 자막만 제공한다고 한다. | 번역 실패와 음성 출력 실패를 분리한다. 번역이 막히면 새 자막도 중단된다. |
| 9 | 모든 429를 짧은 대기로 해결하려 한다. | 분당·일일·토큰·동시 세션·불명 제한을 나눠 처리한다. |
| 10 | 한도가 사용자·키마다 독립된 것처럼 보인다. | 기본 한도 경계는 프로젝트다. 같은 프로젝트의 키를 바꿔도 한도 분리가 아니다. |
| 11 | 앱당 Live 2개 제한이 공용 프로젝트 보호책으로 충분하지 않다. | 기본 Live 1개, 공용 직접 연결의 전역 제어 불가능성을 명시한다. |
| 12 | `localStorage` 저장을 안전한 키 보관으로 취급한다. | 기본 메모리 보관, 선택적 개인 키 저장, XSS·배포망 위험 완화를 적용한다. |
| 13 | 정적 파일은 비밀이 없으므로 어디에 두어도 안전하다고 한다. | 배포된 JS는 실행 중 사용자 키를 읽을 수 있다. 배포 권한과 업데이트도 보안 경계다. |
| 14 | 모델 목록 호출 성공을 통역 연결 확인으로 삼는다. | 실제 REST 번역과 Live를 기능별로 검사한다. |
| 15 | 좌석 마이크를 켜는 것만으로 설교 통역을 충족했다고 본다. | 음질·반향·다중 세션·배터리·공유 한도 검증을 설교 출시 조건으로 둔다. |
| 16 | 전화 통역의 음원 접근 범위가 없다. | 같은 폰의 일반 통화 오디오 직접 캡처를 웹 기능으로 약속하지 않는다. |
| 17 | iOS PWA 문제를 첫 실행 자동 검사 하나로 해결하려 한다. | 사용자 동작 후 캡처·재생 검사, 중단 후 복귀 검사, Safari 경로를 제공한다. |
| 18 | 실제 마이크가 요청한 16kHz로 열린다고 가정하기 쉽다. | 실제 입력 샘플레이트를 확인하고 리샘플링한다. |
| 19 | Live 목소리가 텍스트를 반드시 그대로 읽는다고 가정한다. | 생성형 음성의 누락·첨가·지시 오인을 시험하고 원문 자막을 기준으로 유지한다. |
| 20 | “40턴/4분”을 API 세션 규칙처럼 제시한다. | 앱 운영 정책으로 격리하고 `goAway`·오류·실측으로 조정한다. |
| 21 | 다국어 UI가 P4와 “처음부터”에 동시에 배치되어 있다. | P1부터 세 언어를 모두 제공한다. |
| 22 | APK로 감싸면 백그라운드 오디오가 자동 해결되는 것처럼 쓴다. | 네이티브 오디오 작업과 검증을 별도 구현 범위로 둔다. |
| 23 | 로컬 HTTP 개발 주소를 폰 마이크 테스트에 그대로 쓰기 어렵다. | 실제 폰 시험은 HTTPS 정적 배포 또는 신뢰된 개발 HTTPS로 한다. |
| 24 | 무작위 경로를 접근 제한처럼 제안한다. | 비공개 링크는 인증이 아니다. 공개 앱에 보안 의미를 부여하지 않는다. |
| 25 | 공용 키의 소유권과 대화 기록의 소유권을 혼동한다. | 기록 정책은 대화 프라이버시로 정한다. 공용 모드는 임시 이용 특성상 저장을 끈다. |
| 26 | 새 service worker가 진행 중 통역에 끼치는 영향이 없다. | 통역 중 업데이트 적용을 보류하고 버전 혼합을 막는다. |

Gemini 공식 문서도 한도를 프로젝트 단위로 설명한다. 앱의 사용 카운터는 프로젝트 전체 잔여량을 뜻하지 않는다. [Gemini API 한도](https://ai.google.dev/gemini-api/docs/rate-limits)

## 4. 전체 구조와 지원 범위

### 4.1 기본 구조

```text
정적 HTTPS 호스팅
  └─ HTML / CSS / ES 모듈 / 번역 JSON / service worker
                ↓ 앱 다운로드

사용자 스마트폰
  ├─ 마이크 캡처·리샘플링
  ├─ 순차/동시 상태 관리
  ├─ 키 보관
  ├─ 자막·오디오 재생
  └─ 선택적 로컬 기록
                ↕ HTTPS / WSS
             Gemini API
```

정적 호스트에는 API 키, 음성, 통역문을 보내지 않는다. 다만 정적 파일 요청에 관한 일반 접속 정보는 호스트가 처리할 수 있다.

Google에는 통역에 필요한 음성·텍스트와 인증 정보가 전달된다. “데이터가 폰을 떠나지 않는다”는 문구를 사용하지 않는다.

### 4.2 기본 지원과 제한

| 시나리오 | 제공 방식 | 제한 |
|---|---|---|
| 여행·대면 대화 | 순차 PTT·텍스트 | 순차 재생 중 마이크 입력 중지 |
| 개인 설교 청취 | 동시통역, 좌석의 폰 마이크 | 좌석 음질·각자 프로젝트 한도에 영향 |
| 현장 공용 키 | 해당 회선에서 각자 Gemini 연결 | 공용 프로젝트 한도 공유 |
| 허브 설교 청취 | 현장 허브가 언어별 통역을 방송 | 행사 중 허브 장비 필요 |
| 전화 통역 보조 | 별도 전화기 스피커 소리를 통역 폰으로 입력 | 음향 피드백·개인정보 노출 주의 |
| 같은 폰의 통화 오디오 직접 통역 | v0.5 기본 지원 제외 | OS·통화 앱별 접근 가능성 미검증 |
| 오프라인 | 앱 셸·저장 기록 열람 | 새 AI 통역 불가 |

## 5. 공용 키의 공간 제한과 관리자 운영

### 5.1 보장하려는 경계

공용 키 직접 배포 모드의 조건은 다음과 같다.

1. 공용 전용 키에 **애플리케이션 제한: 행사장 출구 IP**를 설정한다.
2. **API 제한: Gemini API만** 허용한다.
3. 해당 행사장의 실제 REST·Live 경로에서 제한이 작동하는지 검사한다.
4. 행사 종료 후 키를 폐기한다.
5. 제한을 확인하지 못한 행사는 공용 키를 배포하지 않는다.

Google은 IP·IPv6·CIDR 제한을 제공하며, 키마다 애플리케이션 제한 유형은 하나만 선택할 수 있다. 그러나 이 사실만으로 특정 Live 연결의 이동 중 차단 동작까지 확정되지는 않는다. [API 키 제한](https://docs.cloud.google.com/api-keys/docs/add-restrictions-api-keys)

### 5.2 보장하지 못하는 것

다음은 앱의 위치 확인·SSID 확인·QR·세션 저장소로 해결할 수 없다.

- 행사장 VPN 출구나 프록시를 이용하는 외부 사용자.
- 행사장 내부 기기를 원격으로 조작하는 사용자.
- 행사장과 동일한 공인 출구를 공유하는 다른 사용자.
- Wi-Fi 전파가 건물 밖까지 닿는 경우.
- 허용 주소가 다른 가입자에게 재할당되었는데 키가 계속 살아 있는 경우.
- 이미 열린 Live 연결이 이동 후 유지되는 경우의 즉시 차단.
- 복사한 키를 자체 스크립트에서 사용하는 행위.
- 현장 이용자가 생성된 자막·음성을 외부로 재전송하는 행위.

**결론:** 공개 브라우저에 원본 키를 나눠 주는 구조로 “복사한 키는 물리적으로 행사장 밖에서 절대 사용할 수 없다”를 완전히 보장할 수 없다.

v0.5는 이를 숨기지 않는다. 오너가 회선 제한을 공간 한정의 운영 기준으로 받아들이지 않으면 **공용 키 직접 배포 기능은 출시 보류**다. 개인 키 모드는 독립적으로 출시할 수 있다.

### 5.3 네트워크 사전 점검

관리자는 행사 전에 다음을 기록한다.

| 항목 | 처리 |
|---|---|
| IPv4 | 행사장 전용 출구인지 확인 |
| IPv6 | 실제 폰의 Google 연결 경로 확인. 관리 가능한 행사장 범위만 허용 |
| 이중 회선 | 두 출구를 모두 통제할 수 있을 때만 등록 |
| CGNAT·공유 출구 | 행사장 고유 경계로 사용할 수 없다면 직접 배포 보류 |
| 유동 IP | 행사 직전 확인, 종료 시 키 폐기 |
| VPN·프록시 | 행사장 출구를 외부에 제공하는 기능을 운영상 차단 |
| Wi-Fi→LTE 전환 | 신규 REST·Live 및 기존 Live 각각 시험 |
| 제한 변경 전파 | 콘솔 변경 직후 성공을 가정하지 않고 재검사 |

외부 IP 확인 사이트의 결과는 참고값이다. Gemini REST와 WebSocket이 같은 출구를 사용했다는 증거로 삼지 않는다.

브라우저의 온라인 상태나 네트워크 변화 이벤트는 안내·재연결의 단서일 뿐 보안 근거가 아니다.

### 5.4 키 배포 방식

**기본안: 행사별 QR, 메모리 보관.**

- QR은 정적 앱 URL의 fragment로 행사별 키를 전달할 수 있다.
- 앱은 가장 먼저 fragment를 읽고 `history.replaceState`로 제거한다.
- 키는 메모리에만 둔다.
- 새로고침·앱 종료 후 다시 QR을 스캔한다.
- 키가 포함된 QR 이미지는 앱에서 보존하거나 기록에 넣지 않는다.
- QR 인식 앱·화면 캡처·클립보드·브라우저 확장에서 키가 노출될 수 있음을 관리자 문서에 설명한다.
- fragment는 통상 HTTP 요청에 포함되지 않지만 비밀 저장소가 아니다.

개인 키가 이미 있는 사람이 공용 QR을 열면 개인 키 사용을 유지한다. 공용 모드 전환은 사용자가 선택해야 한다.

**선택안: 행사 중 기존 허브가 키 전달.**

- 기존 허브가 안전한 HTTPS 환경에서 현장 접근을 검증할 수 있을 때만 사용한다.
- 키 응답은 `Cache-Control: no-store`.
- 로그·URL·분석 도구에 키를 남기지 않는다.
- `expiresAt`은 정상 앱의 사용 종료 시각이다. Google API 키 자체의 만료가 아니다.
- 방 종료는 추가 전달을 중단한다. 원본 키 회수는 콘솔에서 폐기한다.
- 프록시 환경에서 요청 IP를 판별할 때 임의의 `X-Forwarded-For`를 신뢰하지 않는다.
- 공개 HTTPS 페이지에서 로컬 HTTP 허브를 직접 부르는 경로는 기본안으로 채택하지 않는다.

Live 전용 임시 토큰은 Google이 제공하는 별도 기능이다. 원본 키에 만료 시각을 붙이는 것과 다르며 발급 주체가 필요하다. REST 순차통역 전체를 대체하지도 않는다. 또한 발급 키의 IP 제한이 토큰 연결에 동일하게 적용된다고 가정하지 않는다. v0.5 필수 경로에서는 제외한다. [Live 임시 토큰](https://ai.google.dev/gemini-api/docs/live-api/ephemeral-tokens)

### 5.5 관리자 체크리스트

1. 기존 사용량과 분리된 공용 프로젝트를 준비한다. 한도 우회를 목적으로 프로젝트를 여러 개 만들지 않는다.
2. 무료 이용 상태를 확인하고 자동 유료 전환을 설정하지 않는다.
3. 행사별 키를 발급하고 IP·API 제한을 적용한다.
4. 내부·외부 REST 및 Live 시험을 통과시킨다.
5. 실제 행사 규모로 공용 한도를 시험한다.
6. 검증 결과에 따라 공용 직접 연결 이용 정원을 정한다.
7. QR을 현장에 게시한다.
8. 행사 종료 후 방을 닫고 키를 폐기한다.
9. 폐기 후 신규 REST·Live 연결 거부와 기존 연결 종료 동작을 확인한다.

공용 키가 추출 가능한 이상, 앱의 세션 수·시간 제한은 악의적 사용자에게 강제되지 않는다. 전역 정원과 공정한 사용량 분배가 필요하면 현장 허브가 중계해야 한다.

## 6. 사용자 흐름

### 6.1 공통 첫 실행

1. 링크 또는 QR로 접속한다.
2. `navigator.languages`에서 ko/en/ja를 선택한다. 없으면 영어를 사용한다.
3. 첫 화면에서 `한국어 / English / 日本語`를 바로 바꿀 수 있다.
4. 개인 키 설정 또는 현장 공용 키 사용을 선택한다.
5. 음성·텍스트가 Google로 전송된다는 짧은 안내를 확인한다.
6. 사용자가 마이크 검사 버튼을 누른다.
7. 마이크 입력 레벨과 짧은 재생음을 검사한다.
8. 순차통역 또는 동시통역으로 들어간다.

설치 안내는 첫 통역에 성공한 뒤 제안한다. 앱을 설치해야 통역할 수 있다는 인상을 주지 않는다.

### 6.2 개인 키 모드

- AI Studio에서 본인 프로젝트·키를 준비하는 세 언어 안내 제공.
- 결제 활성화를 키 생성의 필수 단계로 안내하지 않는다.
- 키를 붙여넣으면 기본적으로 현재 실행 동안만 보관한다.
- `이 기기에 키 저장`을 켜면 영구 저장 위험을 설명하고 저장한다.
- REST 번역 연결 검사와 Live 연결 검사를 구분한다.
- REST만 성공하면 순차 텍스트 기능부터 사용할 수 있다.
- 실패한 기능에만 제한 표시를 한다.

앱은 API 키 문자열만으로 해당 프로젝트의 결제 상태나 정확한 무료 잔여량을 확정할 수 없다. 사용자가 AI Studio에서 확인하도록 안내한다.

### 6.3 현장 공용 키 모드

- QR 진입 후 행사명과 `현장 공용 키` 배지를 표시한다.
- “이 행사장 회선에서 사용하도록 제한된 임시 키입니다”라고 설명한다.
- 실제 기능 연결을 검사한다.
- 공용 프로젝트의 한도를 다른 참석자와 공유한다는 점을 안내한다.
- 개인 키가 있으면 개인 키 사용을 기본으로 유지한다.
- 공용 한도 소진 후 개인 키를 자동으로 사용하지 않는다. 사용자가 전환한다.
- `현장 사용 끝내기`는 Live·마이크·오디오·메모리 키·임시 기록을 종료한다.

### 6.4 통역 시작

**순차통역**

1. 언어 쌍을 선택한다.
2. 자동 언어 감지 또는 입력 언어 고정을 선택한다.
3. PTT 버튼을 누르고 말한다.
4. 버튼을 놓으면 번역한다.
5. 원문·번역문을 먼저 표시한다.
6. 가능한 음성 엔진으로 읽는다.
7. 다음 발화를 시작하면 이전 재생을 중지한다.

**동시통역**

1. 원어와 청취 언어를 정한다.
2. 이어폰 사용을 안내한다.
3. 시작 버튼으로 마이크와 오디오를 활성화한다.
4. 자막과 번역 음성을 제공한다.
5. 연결이 끊기면 누락 구간을 표시하고 재연결한다.
6. 중지하면 마이크 트랙·소켓·오디오 큐를 모두 정리한다.

## 7. 화면 명세

### 7.1 공통 셸

상단에는 앱 이름, 키 출처 배지, 연결 상태, 설정 버튼을 둔다.

주 탭은 두 개만 둔다.

- 순차통역
- 동시통역

키 값은 주 화면에 표시하지 않는다. 키 전환·언어 변경·탭 변경으로 활성 세션이 종료될 때는 그 결과를 명확히 알린다.

### 7.2 순차통역 화면

| 요소 | 동작 |
|---|---|
| 언어 쌍·교환 버튼 | UI 언어와 독립 |
| 입력 언어 | 자동 감지 / 한쪽 언어 고정 |
| PTT | 누르고 말하기, 접근성용 시작·종료 대체 버튼 |
| 입력 레벨 | 실제 소리가 들어오는지 표시 |
| 텍스트 입력 | 마이크 실패 시에도 이용 가능 |
| 말풍선 | 원문·번역문·처리 상태·재생 버튼 |
| 재시도 | 동일 턴을 다시 처리하되 중복 기록 방지 |
| 저장 상태 | 기록 OFF / 이 기기에 저장 중 |

상태 흐름:

```text
대기 → 녹음 → 번역 → 표시 → 음성 재생 → 대기
                 └→ 오류 또는 자막만
```

설계값으로 발화 최대 길이를 30초로 둔다. 종료 전 안내하고 자동으로 녹음을 끝낸다. 긴 대화는 발화를 나누거나 동시통역으로 유도한다.

### 7.3 동시통역 화면

- 원어·목표어.
- 시작·중지.
- 마이크 레벨.
- 확정 자막과 임시 자막.
- 소리 켜기·끄기.
- 연결 상태·재연결 상태.
- 실시간에서 지연되고 있음을 나타내는 상태.
- `청취 방식: 내 폰 마이크 / 현장 방송` 선택. 현장 방송은 제공될 때만 노출.

상태 흐름:

```text
대기 → 권한 확인 → 연결 중 → 통역 중
                            ├→ 재연결 중 → 통역 중
                            ├→ 제한으로 중단
                            └→ 사용자 중지
```

“소리 끄기”는 로컬 재생 중지다. 서버의 오디오 생성·과금 단위까지 줄어든다고 표시하지 않는다.

### 7.4 설정

- 표시 언어.
- 통역 언어 기본값.
- 개인 키 입력·연결 검사·삭제.
- 현재 키 출처와 모드 전환.
- 개인 키 영구 저장 선택.
- 음성: Gemini Live / 기기 음성 / 음성 끔.
- Gemini 보이스 선택.
- 기기에서 실제 제공되는 음성 목록.
- 기록 저장·내보내기·전체 삭제.
- 마이크·재생 진단.
- 웹/PWA/APK 실행 형태와 앱 버전.
- 설치·업데이트 안내.
- 무료 한도와 데이터 처리 안내.

자유로운 페르소나 설정은 제외한다. 통역과 읽기 정확도를 우선한다. 음성 선택은 미리듣기를 누를 때만 실행하여 불필요한 Live 세션을 만들지 않는다.

### 7.5 오류 문구와 행동

| 분류 | 한국어 예시 | 제공 행동 |
|---|---|---|
| 마이크 거부 | 마이크 사용이 허용되지 않았어요. | 권한 안내 / 텍스트 입력 |
| 입력 무음 | 마이크는 열렸지만 소리가 감지되지 않아요. | 입력 장치·거리 점검 |
| 재생 차단 | 소리를 재생하려면 버튼을 눌러 주세요. | 재생 활성화 |
| 확인된 IP 차단 | 행사장 회선에서 접속했는지 확인해 주세요. | Wi-Fi 확인 / 개인 키 |
| 기타 인증 실패 | 키 또는 API 사용 권한을 확인해 주세요. | 키 설정 / 진단 |
| 일시적 한도 | 요청이 많아 잠시 기다리고 있어요. | 대기 / 중지 |
| 번역 한도 소진 | 새 통역을 만들 수 없어요. 기존 내용은 볼 수 있어요. | 개인 키 선택 / 나중에 재시도 |
| 음성만 실패 | 번역은 완료됐지만 음성을 만들지 못했어요. | 기기 음성 / 자막 |
| 서비스 혼잡 | 통역 서비스가 혼잡해요. | 제한된 재시도 / 다른 지원 경로 |
| 연결 단절 | 연결이 끊겨 일부 내용이 누락됐어요. | 재연결 |
| 브라우저 중단 | 화면을 벗어나 통역이 중단됐어요. | 탭하여 재개 |

모든 403을 IP 차단으로 처리하지 않는다. WebSocket 실패에서는 상세 HTTP 오류가 브라우저에 노출되지 않을 수 있으므로, 근거가 없으면 `Live 연결 실패`로 표시한다.

## 8. 엔진과 폴백 사다리

### 8.1 공통 엔진 규약

- REST·Live·오디오·기록을 UI에서 분리한다.
- `turnId`, `sessionId`, 연결 세대 번호를 부여한다.
- 종료된 턴이나 이전 연결에서 늦게 도착한 응답을 폐기한다.
- 모델별 지원 기능과 요청 필드를 `model-config.js`에 모은다.
- 미지원 필드를 모든 모델에 공통으로 보내지 않는다.
- Gemini REST 인증은 지원되는 `x-goog-api-key` 헤더를 사용해 URL 노출을 줄인다.
- Live의 키 포함 연결 URL은 로그·오류 보고에서 제거한다.

### 8.2 순차통역

입력 경로:

```text
마이크 → 실제 샘플레이트 확인 → PCM 변환 → WAV
텍스트 ───────────────────────────────────┘
                       ↓
flash-lite, thinking 0
                       ↓ 검증 실패 또는 적용 가능한 모델 오류
3.5-flash
                       ↓
검증된 원문·번역 표시 → 음성 출력
```

검증 항목:

- JSON 구조와 필수 필드.
- 지원 언어 코드.
- 원문·번역문의 존재와 길이.
- 목표 언어 적합성.
- 무음·잡음·인식 불가.
- 번역 대신 질문에 답하거나 지시를 수행했는지.

일본어·한국어·영어가 섞인 짧은 문장, 숫자, 고유명사는 문자 종류만으로 판정하지 않는다. 불확실하면 사용자에게 입력 언어 고정을 제공한다.

발화 내용은 번역할 데이터로 취급한다. “이전 지시를 무시하라” 같은 발화가 앱 프롬프트를 바꾸지 않도록 프롬프트와 구조를 분리한다. 모델만으로 완벽한 방어를 보장하지는 않는다.

정상 품질 캐스케이드는 턴당 최대 2회다. 재시도는 §9의 총 호출 예산 안에서만 실행한다.

### 8.3 Live 목소리

- 기본: `gemini-3.1-flash-live-preview`.
- 입력: 확정된 번역문 텍스트 턴.
- 출력: PCM16 24kHz.
- 지시: 전달한 내용을 읽고 설명·대답·추가 문장을 만들지 않는다.
- 한 번에 한 텍스트만 재생한다.
- 취소 시 큐를 비우고 이전 턴의 후속 오디오를 무시한다.
- 세션 교체는 턴 경계에서 시행한다.

v0.4의 40턴·4분 유휴는 검증된 API 한도가 아니다. 초기 세션 정책의 참고값으로만 유지하고 실측 후 설정한다. 페이지를 벗어나거나 다른 통역 모드로 전환하면 유휴 타이머와 관계없이 닫는다.

폴백:

```text
Live 목소리
  → 해당 언어의 기기 speechSynthesis
  → 자막만
```

기기 TTS의 언어·음성·오프라인 가능 여부는 실제 기기에서 확인한다. 기기 음성이 반드시 로컬에서만 처리된다고 약속하지 않는다.

생성형 Live 음성이 글을 바꿔 읽을 가능성은 남는다. 자막을 기준 기록으로 유지하고, 제공 가능한 전사 정보와 실청취로 누락·첨가를 시험한다. 완전한 음성 일치 보장은 하지 않는다.

TTS API 두 모델과 맥 전용 Qwen3-TTS·`say`는 폰 엔진에서 제외한다.

### 8.4 동시통역

기본 경로:

```text
마이크 PCM16 16kHz
  → gemini-3.5-live-translate-preview
  → PCM16 24kHz + outputTranscription
```

- `translationConfig`를 사용한다.
- 이 모델에 시스템 프롬프트를 보내지 않는다.
- 32ms 업링크 프레임은 초기 설계값이다.
- 실제 장치 입력을 16kHz로 리샘플링한다.
- 오디오 재생은 AudioContext 시간 기준으로 예약한다.
- SegmentAssembler는 부분·확정·중단 자막을 구분한다.
- 원문 전사를 받지 못하는 경로에서는 번역문을 원문처럼 표시하지 않는다.

폴백 사다리:

| 순서 | 경로 | 조건 |
|---|---|---|
| 1 | 번역 전용 Live | 기본 |
| 2 | flash-live 통역 프롬프트 | 모델 미지원·일시 장애 등이고 해당 경로가 이용 가능할 때 |
| 3 | 짧게 나눠 순차통역 | REST가 살아 있을 때 사용자가 선택 |
| 4 | 새 통역 중단 | 사용할 번역 경로가 없을 때 |

3단계는 동시통역 성능으로 표시하지 않는다. “짧게 나눠 통역”으로 상태를 바꾼다. 공용 모드에서는 자동으로 REST 요청을 반복하지 않는다.

동시통역이 생성한 오디오는 직접 재생한다. 같은 자막을 별도의 목소리 Live 세션에 보내지 않는다.

### 8.5 오디오 흐름과 과부하

- 순차통역 재생 중에는 녹음하지 않는다.
- 동시통역은 이어폰 사용을 기본 안내한다.
- 스피커 출력이 다시 마이크에 들어가면 번역 루프가 생길 수 있다.
- echo cancellation은 보조 수단이며 완전한 해결책이 아니다.
- 송신·수신 큐 크기에 상한을 둔다.
- 지연이 계속 누적되면 과거 오디오를 무한 재생하지 않는다.
- 설계값으로 재생 대기 3초에서 지연 상태를 표시하고, 8초 초과 시 구간 경계에서 최신 상태로 복귀한다.
- 버린 구간은 누락 표시를 남긴다.
- 네트워크 복구 후 녹음 전체를 자동 재전송하지 않는다.

큐 임계값은 실제 설교 시험 후 조정한다.

## 9. 한도·429·503·세션 관리

### 9.1 기본 정책

- 앱 인스턴스당 활성 Live 세션은 기본 1개다.
- 순차 목소리와 동시통역을 동시에 열지 않는다.
- 세션 교체는 기존 연결 종료 후 새 연결을 연다.
- 같은 origin의 여러 탭은 가능한 경우 `BroadcastChannel` 등으로 활성 상태를 조정한다.
- 다른 브라우저·기기·임의 클라이언트까지 이 제한을 강제할 수는 없다.

프로젝트 전체 잔여량을 알 수 없으면 “남은 횟수”를 표시하지 않는다. 표시 가능한 것은 현재 기기에서 관측한 호출 수·연결 시간·마지막 오류다.

### 9.2 오류별 처리

| 오류 | 처리 |
|---|---|
| 키 무효·권한 거부 | 자동 재시도 중단, 설정 안내 |
| 확인된 IP 거부 | 공용 연결 중단, Wi-Fi·관리자 안내 |
| 분당 제한 | 제공된 재시도 정보를 따르고 지터를 둔 대기 |
| 일일 소진 | 반복 재시도 금지, 정확한 재개 시각을 모르면 시각 미확인 표시 |
| 동시 세션 제한 | 기존 세션 종료 확인, 대기 후 제한된 재연결 |
| 토큰·세션 관련 제한 | 서버 오류 정보에 맞게 처리. 새 세션이 해결책인지 확인 |
| 원인 불명 429 | 오늘 소진이라고 단정하지 않고 자동 반복 억제 |
| 503·일시 네트워크 오류 | 제한된 재시도와 지원 모델 폴백 |
| 모델·설정 미지원 | 설정 교정 또는 알려진 폴백 |
| 안전 차단·내용 거부 | 우회 목적의 모델 순환 금지 |

### 9.3 재시도 예산

초기 설계값:

- 순차통역: 한 사용자 턴당 총 자동 API 시도 최대 3회. 기본·폴백·일시 오류 재시도를 모두 포함한다.
- Live 재연결: 약 1초·2초·4초 간격에 지터를 추가하여 최대 3회.
- 서버가 더 긴 대기를 요구하면 그 값을 우선한다.
- 연속 실패 후에는 자동 반복을 멈추고 재시도 버튼을 제공한다.
- 키 또는 모드 변경 시 이전 재시도 작업을 취소한다.

카운트다운은 “다음 시도까지”다. 한도가 반드시 그때 회복된다는 뜻으로 표시하지 않는다.

### 9.4 한도 소진 시 기능 구분

| 상태 | 남는 기능 |
|---|---|
| Live 목소리만 실패 | 새 REST 번역·기기 TTS·자막 |
| 동시 Live 실패, REST 가능 | 사용자가 선택한 짧은 순차통역 |
| REST 실패, 기존 번역 있음 | 기존 번역 보기·가능한 기기 TTS |
| 모든 번역 경로 실패 | 기존 기록 열람·입력 초안·키 설정 |
| 인터넷 없음 | 로컬 셸·저장 기록 |

공용 한도 소진 시 다른 공용 키를 자동 순환하지 않는다. 개인 키 전환은 사용자의 명시적 선택으로만 한다.

## 10. 설교 통역 운영

### 10.1 허브 없이 각자 폰 사용

장점은 개인 맥이나 현장 서버가 필요 없다는 것이다.

그러나 다음 조건을 충족해야 한다.

- 각 좌석에서 강단 소리가 명료하게 들어와야 한다.
- 청중은 이어폰을 사용한다.
- 폰은 전경에서 동작하고 화면 잠금 시 중단 가능성을 안내한다.
- 각자 개인 프로젝트를 쓰면 한도는 분산되지만 청중 수만큼 Live 연결이 생긴다.
- 공용 키를 쓰면 동일 프로젝트의 세션·토큰 한도에 집중된다.
- 소음·잔향·박수·기도·찬양을 통역기로 입력할지 운영자가 구분한다.

**추정 용량 계산:** 무압축 PCM만 계산하면 사용자 1명의 입력은 약 32KB/s, 연속 오디오 출력은 약 48KB/s다. 합계 약 80KB/s이며 Base64·프로토콜 오버헤드는 별도다. 100명이 계속 송수신하면 원시 오디오만 약 8MB/s 규모다. 실제 출력 점유율·프레이밍에 따라 달라지므로 현장 측정으로 확정한다.

“개인 폰으로 10분 성공”은 “100명이 예배 한 시간 사용 가능”의 증거가 아니다.

### 10.2 기존 현장 허브 사용

```text
믹서 또는 강단 입력
       ↓
행사 중 켠 기존 허브
       ├─ 목표 언어 A Live → A 청중
       ├─ 목표 언어 B Live → B 청중
       └─ 목표 언어 C Live → C 청중
```

- 언어별 한 세션으로 공유하는 구조를 우선한다.
- 청중 폰은 마이크와 Gemini 키 없이 해당 방송을 받을 수 있다.
- 이 경우 Gemini 사용 주체는 관리자다. 청중의 키 모드가 새로 생기는 것이 아니라 현장 방송을 듣는 것이다.
- 공용 키는 허브에만 보관할 수 있다.
- 중앙 세션·정원·종료를 제어할 수 있다.
- 행사 중에만 기존 장비를 켠다. 상시 서버는 아니다.

허브는 음질과 API 세션 수를 개선하지만 네트워크 부하를 없애지는 않는다. 브라우저로 개별 전송하면 청중 수만큼 LAN 하향 트래픽이 발생한다.

실기기 시험 전에는 기존 방송 허브가 모바일까지 검증됐다고 간주하지 않는다.

### 10.3 허브의 전송·접속 조건

- 오디오와 자막에 순서 번호·세션 번호·시간 정보를 부여한다.
- 늦게 입장한 사용자는 현재 시점부터 듣는다.
- 느린 청중 한 명이 다른 청중의 전송을 막지 않게 큐를 분리한다.
- 지연이 누적된 청중은 최신 구간으로 복귀한다.
- 방 종료 시 서버가 수신 연결을 닫는다.
- 허브 서비스는 행사장 네트워크에만 노출하는 구성을 우선한다.
- 게스트 Wi-Fi의 기기 간 통신 차단이 허브 접속을 막는지 확인한다.
- HTTPS/WSS 인증서·DNS·브라우저의 로컬 네트워크 접근을 검증한다.
- 안전한 로컬 HTTPS 경로를 기존 인프라로 만들 수 없으면 허브 기능을 보류한다.

허브 고장 후 청중 모두를 공용 Live에 자동 연결하지 않는다. 개인 키 이용자는 직접 모드로 전환할 수 있고, 나머지는 운영자가 대체 안내한다.

## 11. 키 저장과 보안

### 11.1 저장 정책

| 데이터 | 기본 위치 | 유지 |
|---|---|---|
| 개인 키 | 메모리 | 현재 실행 |
| 저장을 선택한 개인 키 | 브라우저 로컬 저장소 | 사용자가 삭제할 때까지, 브라우저 정책에 따라 소실 가능 |
| 공용 키 | 메모리만 | 현장 사용 종료·페이지 종료까지 |
| UI 설정 | localStorage | 기기별 |
| 저장 기록 | IndexedDB | 사용자 설정에 따라 |
| 오디오 원본 | 메모리 | 해당 처리에 필요한 동안 |
| 정적 파일 | Cache Storage | 앱 버전별 |

브라우저 저장소를 암호화 저장소라고 부르지 않는다. IndexedDB로 바꿔도 동일 origin의 악성 JS가 읽을 수 있다는 문제는 같다.

앱 PIN은 v0.5에서 제외한다. 단순 화면 잠금을 키 암호화처럼 오해하게 만들지 않는다. 암호화 저장을 도입하려면 비밀번호·키 유도·복구 정책을 별도로 설계한다.

APK에서는 OS 보안 저장소 연동을 구현·검증한 뒤 영구 키 저장에 사용한다. 그래도 실행 중 메모리 노출이나 감염된 기기까지 보호하지는 못한다.

### 11.2 필수 완화

- 앱 전용 origin 사용.
- 외부 광고·분석 SDK·외부 실행 스크립트 금지.
- 번역문·원문은 HTML로 해석하지 않고 텍스트로 렌더링.
- `eval`·동적 코드 실행 금지.
- CSP로 스크립트와 네트워크 목적지를 제한.
- 키 포함 URL·헤더·오류 원문 로깅 금지.
- service worker는 Gemini 요청·키·기록을 캐시하지 않음.
- 키 입력 필드의 자동완성·자동수정 최소화.
- 키 전체 보기·복사 기능은 기본 제공하지 않음.
- 저장소·배포 산출물에 키가 섞였는지 검사.
- 배포 계정 보호와 릴리스 변경 검토.
- 키 삭제 시 활성 요청·세션도 중지.

키 삭제는 로컬 보관을 지우는 기능이다. 이미 유출된 키를 무효화하려면 Google 콘솔에서 폐기해야 한다. JavaScript 메모리의 즉시 완전 소거는 보장하지 않는다.

### 11.3 개인 키 제한

- Gemini API만 허용하는 API 제한을 안내한다.
- 장소 제약이 없는 사용이 목적이므로 개인 키에 행사장 IP 제한을 권하지 않는다.
- HTTP referrer 제한은 REST·Live·PWA·APK 조합에서 검증한 경우에만 안내한다.
- referrer 제한을 모든 클라이언트에 통용되는 보호책으로 단정하지 않는다.

### 11.4 무료 서비스 데이터 처리와 이용 가능 범위

무료 API의 데이터 처리 정책은 앱의 로컬 기록 OFF와 별개다. Google 공식 약관은 무료 서비스의 입력·출력 활용과 연령 관련 조건을 명시한다. 이용 지역에 따른 조항도 있으므로 실제 서비스 대상에 맞게 확인해야 한다. [Gemini API 추가 약관](https://ai.google.dev/gemini-api/terms?authuser=00)

따라서 다음을 공개 출시 조건에 포함한다.

- 음성·텍스트의 Google 전송 및 무료 서비스 데이터 처리 안내.
- 민감한 대화 입력에 관한 해당 서비스 조건 반영.
- 미성년자를 포함하는 “모두”와 API 이용 조건의 충돌 확인.
- 공용 키 배포 운영이 적용 조건을 충족하는지 확인.

이는 오너 취지를 임의로 축소하는 결정이 아니다. 현재 공급자 조건 때문에 구현만으로 해결할 수 없는 출시 위험이다.

## 12. i18n과 접근성

- `ko.json`, `en.json`, `ja.json`을 P1부터 같은 키로 유지한다.
- 언어 선택은 `ko-KR → ko`, `ja-JP → ja`, `en-US → en`처럼 정규화한다.
- 지원되지 않는 표시 언어는 영어로 폴백한다.
- UI 언어와 통역 언어는 별도로 저장한다.
- 기본 통역 쌍은 UI 언어와 다른 지원 언어로 제안하되 첫 사용자가 확인할 수 있게 한다.
- 오류·키 생성 안내·한도·설치·기록·삭제 문구까지 번역한다.
- API 원문 오류를 사용자 메시지로 그대로 노출하지 않는다.
- 날짜·숫자·시간은 `Intl`로 표시한다.
- 언어별 문자열 누락 검사를 배포 전 실행한다.
- 텍스트 확대·스크린리더·충분한 터치 영역·색상 외 상태 표현을 제공한다.

manifest는 언어별 파일로 제공한다. 하나의 `short_name`에 임의의 다국어 맵을 넣지 않는다. 설치된 앱 이름이 UI 언어 변경 즉시 갱신된다고 약속하지 않는다.

## 13. PWA·iOS·APK·정적 배포

### 13.1 정적 배포

기본 배포안은 Cloudflare Pages 무료 정적 호스팅이다. 서버 함수·유료 부가 기능을 사용하지 않는다. 정적 HTML 직접 배포와 무료 플랜 제한은 공식 문서에서 확인할 수 있다. [정적 HTML 배포](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/), [Pages 제한](https://developers.cloudflare.com/pages/platform/limits/)

- 무료 제공 도메인으로 시작한다.
- 새 도메인 구매는 필수가 아니다.
- `_headers`에 CSP 등 보안 헤더를 명시한다.
- 공개 소스와 비공개 소스 여부는 비밀 보호 수단으로 삼지 않는다.
- GitHub Pages는 대체 가능하지만 보안 헤더와 배포 요구사항을 다시 확인한다.
- 개발용 폰 접속도 HTTPS를 사용한다.

### 13.2 service worker

- 정적 앱 셸만 캐시한다.
- 캐시 이름에 릴리스 버전을 포함한다.
- 설치 단계에서 해당 버전 파일을 완전히 확보한다.
- 통역 중에는 새 버전 활성화를 보류한다.
- 사용자가 통역을 끝낸 뒤 업데이트한다.
- 이전 버전과 새 버전 모듈이 섞이지 않게 한다.
- 실패한 배포는 이전 정적 릴리스로 복구한다.
- IndexedDB 변경은 이전 데이터 보존을 우선한다.
- 오프라인 첫 방문은 지원하지 않는다.
- 오프라인 셸 성공을 오프라인 통역 성공으로 표시하지 않는다.

### 13.3 iOS 실전 대응

WebKit에는 홈 화면 웹 앱의 마이크 지원 이력과 관련 수정 기록이 있다. 이것만으로 현재 대상 iPhone의 안정성을 보장할 수는 없다. 본 앱의 iOS PWA 마이크는 계속 미검증으로 취급한다. [WebKit 관련 이슈](https://bugs.webkit.org/show_bug.cgi?id=185448)

검사는 사용자 버튼 동작 이후 수행한다.

1. `getUserMedia` 성공 확인.
2. 실제 음성 입력 레벨 확인.
3. AudioWorklet 처리 확인.
4. AudioContext 활성화와 재생 확인.
5. 짧은 REST·Live 실제 연결 확인.
6. 중지 후 재시작 확인.
7. 화면 잠금·앱 전환·전화 수신 후 복귀 확인.

실패 시:

- 권한 거부·무음·캡처 중단·재생 차단을 구분한다.
- 현재 기능이 가능한 경우 텍스트 통역을 제공한다.
- Safari에서 같은 앱 주소를 여는 절차와 URL 복사를 제공한다.
- PWA에서 Safari를 항상 강제로 열 수 있다고 가정하지 않는다.
- 키·기록이 Safari와 PWA 사이에 자동 공유된다고 가정하지 않는다.
- 공용 키는 필요 시 QR을 다시 스캔한다.
- Safari에서도 실패하면 마이크 통역 미지원 상태를 표시한다.

웹/PWA의 기준 동작은 **화면이 켜진 전경 상태**다. 잠금 화면·백그라운드 지속 녹음은 보장하지 않는다.

### 13.4 Android APK

- Capacitor로 동일 웹 자산을 패키징한다.
- APK를 서명하여 무료로 직접 배포한다.
- 사이트에 버전·변경 사항·파일 해시·설치 안내를 제공한다.
- 업데이트 APK는 같은 서명 키를 사용한다.
- 서명 키는 소스 저장소에 넣지 않고 백업한다.
- APK에 개인·공용 Gemini 키를 포함하지 않는다.
- 앱 내부 다운로드·재설치 동작은 실제 대상 Android에서 검증한다.

Capacitor는 네이티브 API를 연결하는 실행 환경이다. 단순 패키징만으로 네이티브 오디오 구현이 완성되지는 않는다. [Capacitor](https://capacitorjs.com/)

백그라운드 마이크는 Android foreground service·권한·시작 조건 등의 영향을 받는다. 따라서 네이티브 오디오 세션과 중단 복구를 구현하고 시험한 기능만 활성화한다. [Android foreground service 유형](https://developer.android.com/develop/background-work/services/fgs/service-types)

웹 런타임은 빌드 도구 없는 ES 모듈을 유지한다. APK 생성에는 Android SDK·Gradle·Capacitor 도구가 필요하며, 이 둘을 혼동하지 않는다.

### 13.5 스토어

- Google Play 등록 관련 비용: **오너 승인 필요**.
- Apple 개발자 프로그램·App Store 관련 비용: **오너 승인 필요**.
- 실제 금액·지역·계정 조건은 신청 시 확인한다.
- 승인 전 기본 제공은 웹/PWA와 무료 Android APK다.
- iOS 일반 사용자용 네이티브 앱 무료 배포를 확정 경로로 제시하지 않는다.

## 14. 데이터·기록·xlsx

### 14.1 기본 정책

- 기록 저장 기본 OFF.
- 저장 OFF에서도 현재 화면 표시를 위한 임시 메모리는 사용한다.
- 개인 모드에서만 로컬 기록 저장을 선택할 수 있다.
- 공용 모드는 영구 기록·파일 내보내기를 기본 차단한다.
- 공용 제한은 정상 앱의 프라이버시 기본값이며 화면 캡처까지 막는 보안 기능은 아니다.
- 원본 오디오는 저장하지 않는다.
- 분석용 서버 업로드는 없다.

### 14.2 기록 구조

세션:

```text
id
startedAt / endedAt
mode: seq | sim | hub-listen
sourceLanguage / targetLanguage
keySource: personal | shared | hub
schemaVersion
```

문장 또는 구간:

```text
id / sessionId / turnId
sequence
startedAt / finalizedAt
sourceText: 선택
translatedText
status: final | partial | interrupted | failed
model
gapBefore
revisionOf: 선택
```

키·키 해시·인증 URL·원본 음성은 기록에 넣지 않는다.

동시 자막의 임시 수정은 메모리에서 처리하고 확정 시 저장한다. 연결 종료로 확정되지 못한 구간은 `interrupted`로 표시한다.

### 14.3 저장·삭제·복구

- IndexedDB 저장 실패 시 통역을 중단하지 않는다.
- “기록을 저장하지 못함”을 표시한다.
- 브라우저 저장소는 OS나 사용자가 삭제할 수 있다.
- 기본 보관 기간은 30일이라는 설계값을 적용하고 사용자가 더 짧게 설정할 수 있게 한다.
- 전체 삭제는 기록·설정·저장 키를 구분해 선택할 수 있다.
- 공용 사용 종료는 현재 임시 기록과 키를 함께 지운다.
- 화면 렌더링은 최근 구간 중심으로 제한해 장시간 DOM 누적을 막는다.

### 14.4 xlsx

기존 의존성 없는 작성기를 브라우저용으로 이식하되 `Buffer`·파일 시스템 등 Node 의존성을 제거한다.

열:

- 시각.
- 통역 모드.
- 원어·목표어.
- 원문.
- 번역문.
- 상태.
- 누락 구간 표시.

조건:

- 텍스트는 수식이 아닌 문자열 셀로 기록한다.
- XML 특수문자·금지 제어문자를 처리한다.
- 사용자 입력을 외부 링크나 수식으로 자동 변환하지 않는다.
- 날짜·시간대 표기를 명시한다.
- Excel·LibreOffice 등에서 열어 문자·행 구분을 확인한다.
- 모바일 다운로드·공유는 기능 감지 후 제공한다.
- 파일이 앱 밖으로 나간 뒤에는 앱의 기록 삭제로 지워지지 않음을 안내한다.

## 16. 단계별 산출물과 완료 기준

### P1 — 독립 순차통역과 공용 키 보안 검증

산출물:

- HTTPS 웹 앱.
- 개인 키·공용 QR·키 삭제.
- 한국어·영어·일본어 UI.
- 텍스트·PTT 순차통역.
- Live 목소리·기기 TTS 폴백.
- 오류 분류와 재시도 예산.
- 저장 OFF 기본값.

완료 기준:

- Android Chrome과 iPhone Safari에서 실제 키로 시험.
- ko↔ja, ko↔en, en↔ja의 6방향을 방향당 10발화 시험.
- 모든 턴이 결과 또는 명시적 오류로 종료.
- 중복 재생·중복 기록 없음.
- 짧은 발화의 PTT 종료→첫소리 지연을 측정.
- 따뜻한 세션의 p50 3초 이하를 목표로 하고 p95·차가운 시작은 별도 보고.
- 목표 미달은 숨기지 않고 원인과 지원 조건을 기록.
- 실제 공용 키로 내부·외부 REST·Live 신규 연결 시험.
- 네트워크 이동 중 기존 Live 동작 기록.
- 앱 로그·스토리지·캐시에 공용 키가 남지 않음.
- 배포 산출물에 키 없음.

공용 보안 검증 실패 시 개인 모드만 P1 완료로 출시 가능하다. 공용 모드 완료로 표시하지 않는다.

### P2 — 동시통역과 설교 운영 검증

산출물:

- 번역 전용 Live와 flash-live 폴백.
- 자막 조립·재생 큐·취소.
- 재연결·누락 표시.
- 허브 없는 설교 청취.
- 기존 허브 수신 경로와 현장 운영 문서.

완료 기준:

- 10분 녹음 시험 후 실제 설교 길이의 60분 연속 시험.
- 3개 청취 언어 시험.
- `goAway`·강제 단절·429·503·오디오 중단 시험.
- 누적 지연·자막 중복·메모리 지속 증가 여부 확인.
- 앞·중간·뒤 좌석의 인식·번역 품질 비교.
- 실제 목표 인원에서 Wi-Fi·공용 한도 검증.
- 허브 사용 시 HTTPS·게스트 Wi-Fi·늦은 입장·느린 수신자 시험.
- 검증된 인원과 조건만 운영 가능 범위로 발표.

### P3 — PWA·기록·안정적 배포

산출물:

- 세 언어 manifest.
- 오프라인 셸.
- 통역 중 업데이트 보류.
- iOS Safari 전환 안내.
- IndexedDB 기록·xlsx.
- 삭제·저장 실패 처리.

완료 기준:

- 실패 조합은 지원표와 앱 안내에 반영.
- 키가 없는 오프라인 상태에서도 셸과 기존 기록 열람.
- 업데이트 중 진행 중 통역이 강제로 끊기지 않음.
- 새 버전 설치 실패 후 이전 버전 실행.

### P4 — 무료 Android APK와 운영 완성

산출물:

- 사이트 다운로드와 업데이트 안내.
- 네이티브 키 저장 어댑터.

완료 기준:

- 업데이트 후 키·설정·기록 처리 검증.

- 백그라운드 기능은 구현·실측한 범위만 지원으로 표시.

- 유료 서비스·키 내장·상시 운영 서버 없음.

스토어 등록은 P4의 필수 완료 조건이 아니다.

| 연결 중 이동 | Wi-Fi→LTE, LTE→Wi-Fi, VPN 사용 |
| 키 폐기 | 신규 요청과 이미 열린 연결의 차이 |
| 모델 폴백 | 실제 지원 모델·요청 필드·실패 코드 |
| 공용 한도 | 실제 프로젝트의 동시 세션·토큰 병목 |
| 기기 TTS | 세 언어 음성 유무·발음·오프라인 동작 |
| Live 읽기 | 숫자·성경 구절·고유명사·명령형 문장 정확도 |

일일 한도를 일부러 전부 소진하는 시험은 일상적으로 반복하지 않는다. 오류 처리 대부분은 재현 가능한 모의 응답으로 검증하고, 실제 제한 동작은 통제된 실키 시험으로 확인한다.

### 17.2 실제 기기 시험

최소 시험군:

- 현재 사용 중인 iPhone Safari.
- 같은 iPhone의 홈 화면 앱.
- 사용 가능한 이전 iOS 기기.
- Android Chrome.
- Android PWA.
- Android APK.
- 유선 또는 USB 오디오 장치, Bluetooth 이어폰.

기기별로 OS·브라우저·WebView 버전과 시험 날짜를 기록한다. “iOS 지원”처럼 버전 없는 포괄적 결과를 쓰지 않는다.

### 17.3 측정 항목

- 녹음 종료→REST 결과.
- 번역문 확정→첫 오디오 수신.
- 첫 오디오 수신→실제 첫소리.
- 발화 종료→첫소리 전체 지연.
- 차가운 세션·따뜻한 세션 차이.
- p50·p95·최대 지연.
- 동시통역 청취 지연과 누락 구간.
- 60분 배터리 감소·발열·메모리.
- 연결당 송수신량.
- 공용 동시 접속 수와 오류율.
- 원문·번역 정확도와 음성 읽기 정확도.

정확도는 단순 언어 코드 일치만으로 평가하지 않는다. 최소한 이중언어 검토자가 부정문·숫자·이름·핵심 의미의 오역을 분류한다. 설교에서는 성경 인명·장절·인용문·교회 용어를 포함한다.

### 17.4 자동 검사

- 번역 스키마와 언어 검증의 경계 사례.
- SegmentAssembler의 부분·확정·중단·재연결.
- 이전 연결 응답 폐기.
- 취소 후 오디오 재생 금지.
- 재시도 예산 초과 금지.
- i18n 키 일치.
- xlsx 텍스트 안전성.
- 캐시에 비밀·API 응답이 들어가지 않는지.
- 릴리스 파일의 비밀 문자열 검사.

출시 근거로 쓰는 진단 자료에는 키·발화 원문을 기본 포함하지 않는다.

## 18. 오너가 결정해야 할 항목

다음만 오너 결정으로 남긴다. 파일 분리·재시도 횟수·UI 기본값 같은 구현 선택은 설계자가 책임지고 진행한다.

| 결정 항목 | 추천안 |
|---|---|
| **공간 한정의 승인 기준:** 행사장 회선 제한과 알려진 우회 가능성을 허용할 것인가? | 직접 공용 키는 검증된 행사장 회선 제한으로 운영하고 정확히 고지한다. 물리적 위치의 절대 보장이 필요하면 직접 배포를 보류하고 현장 허브로 제한한다. |
| **실제 행사 목표 규모:** 동시 청취 인원·언어 수·예배 길이는 얼마인가? | 최대 예상 참석 인원과 전체 예배 길이를 기준으로 용량 시험하고, 개인 키 직접 사용을 기본으로 하되 대규모·공용 사용은 기존 허브를 우선한다. |
| **현장 허브 운영 허용:** 행사 중 기존 맥 또는 기존 장비를 켜는 운영을 채택할 것인가? | 설교에서는 허용한다. 개인 앱의 필수 의존성으로 만들지는 않는다. |
| **“모두”와 공급자 이용 조건의 충돌:** 미성년자 등을 포함한 공개 제공 범위를 어떻게 처리할 것인가? | 취지는 유지하되 적용 조건을 확인하기 전 해당 대상까지 사용 가능하다고 홍보하지 않는다. 조건을 충족할 수 없는 범위는 미충족 요구로 남긴다. |
| **스토어 비용 승인:** Play·App Store 등록을 진행할 것인가? | 우선 승인 없이 웹/PWA·무료 APK를 완성하고, 실제 수요가 확인된 뒤 별도로 승인한다. |

공용 모드의 보안 경계를 아직 승인하지 않은 상태에서는 개인 모드 구현·배포 준비를 계속할 수 있다. 이를 이유로 전체 앱 개발을 멈추지 않는다.

## 19. 열린 위험과 출시 보류 조건

| 위험 | 대응·출시 조건 |
|---|---|
| Live에 대한 IP 제한 동작 미검증 | 공용 직접 배포 전 필수 실키 시험 |
| 물리적 위치의 절대 제한 불가능 | 오너의 보안 경계 결정 필요 |
| 무료 공용 한도의 행사 수용량 부족 | 정원 축소·개인 키·현장 허브. 유료 자동 전환 없음 |
| iOS PWA 캡처·재생 불안정 | Safari 경로와 기기별 지원표 |
| 미리보기 모델 변경·중단 | 설정 집중화·기능별 검사·검증된 폴백 |
| Live 목소리의 누락·첨가 | 자막 기준 유지·읽기 정확도 시험·기기 TTS 선택 |
| 좌석 마이크 음질 부족 | 좌석 시험·입력 위치 개선·기존 믹서 허브 |
| 현장 LAN의 HTTPS·격리 문제 | 실제 게스트 Wi-Fi 시험 전 허브 지원 보류 |
| 무료 서비스 이용 조건과 공개 대상 충돌 | 대상 범위 확인 전 해당 공개 주장 보류 |
| 브라우저 저장소·배포 JS를 통한 키 노출 | 메모리 기본·선택 저장·배포 보안·폐기 절차 |
| 통화 오디오 직접 접근 불가 | 별도 기기 기반 전화 통역 보조만 기본 지원 |
| 공급자가 브라우저 직접 연결을 변경 | 영향 기능 중단·대안 검토. VM·유료 중계를 자동 도입하지 않음 |

v0.5의 완료는 화면과 API 호출을 붙이는 데서 끝나지 않는다. **개인 키로 독립 실행되는 통역**, **검증된 경계 안에서만 제공되는 공용 모드**, **한도 소진을 정직하게 설명하는 복구 흐름**, **실제 설교 길이와 모바일 환경에서 확인한 지원 범위**를 함께 제공해야 한다.
