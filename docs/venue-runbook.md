# 행사장 공용 키 운영 런북 (P1-21)

기준 설계: `design-v0.6.md` §5(공용 키의 공간 제한과 관리자 운영), §6.3, §7.5, §9(한도·오류), §10(설교 통역 운영), §11(키 보안), §19. 관리자가 행사마다 따르는 절차다.

**현재 상태(2026-09-05):** 공용 직접 경로는 **미검증**이다(`device-matrix.md` §6). 이 문서는 절차이지 합격 기록이 아니다. §3의 제한 시험을 실제 행사 회선에서 통과한 기능에만 공용 키를 배포한다(§5.1 조건 5).

## 1. 운영 경계 (승인된 정책)

보장하려는 것(§5.1):

1. 행사별 키에 관리 가능한 행사장 출구 IP 제한을 건다.
2. 해당 API(Gemini API)만 허용하는 API 제한을 건다.
3. 사용하려는 능력(REST 번역·STT, Live 목소리)의 실제 경로에서 내부 허용·외부 거부를 확인한다.
4. 행사 종료 후 제공자 콘솔에서 키를 폐기한다.
5. 제한 동작을 확인하지 못한 기능에는 공용 키를 배포하지 않는다.

보장하지 못하는 것(§5.2): VPN·프록시·원격제어를 통한 외부 이용, 같은 공인 출구를 쓰는 외부 이용자 구별, 건물 밖으로 새는 Wi-Fi, 출구 IP 재할당 후 살아 있는 키, 이미 열린 Live 연결의 이동 직후 차단, 복사한 키의 별도 클라이언트 사용, 자막·음성의 외부 재전송. 앱의 세션 수·시간 제한은 키를 추출한 사용자에게 강제되지 않는다(§5.5).

참석자 안내 문구는 다음으로 통일한다.

> 이 공용 키는 검증된 행사장 회선에서 사용하도록 제한됩니다. 물리적 위치를 확인하는 기능은 아니며, 이미 열린 연결의 즉시 차단을 보장하지 않습니다.

P1 공용 제공자는 Gemini 하나다. 다른 제공자가 같은 제한을 제공한다고 가정하지 않는다.

## 2. 행사 전 준비

### 2.1 공용 프로젝트·키 발급 (§5.5 1~3)

| 단계 | 작업 | 확인 |
|---|---|---|
| 1 | 기존 개인 사용량과 분리된 **공용 Gemini 프로젝트**를 준비한다. 한도 우회 목적으로 프로젝트를 여러 개 만들지 않는다 | 프로젝트 이름 기록 |
| 2 | 무료 이용 상태를 확인하고 **자동 유료 전환·결제를 설정하지 않는다**(§1 9) | 결제 비활성 확인일 기록 |
| 3 | **행사별 새 키**를 발급한다. 이전 행사 키를 재사용하지 않는다 | 키 이름(값 아님)·발급일 기록 |
| 4 | 키에 **IP 제한**을 건다: §2.2에서 확인한 행사장 출구 주소만 | 등록 주소·시각 기록 |
| 5 | 키에 **API 제한**을 건다: Generative Language(Gemini) API만 | 확인 |
| 6 | 콘솔 변경 직후 성공을 가정하지 않고 §3 시험으로 재검사한다(§5.3) | |

키 값은 관리자 기록·채팅·사진·이 문서에 남기지 않는다(§17.4).

### 2.2 네트워크 사전 점검 (§5.3)

행사 전에 다음을 기록한다.

| 항목 | 처리 | 기록 |
|---|---|---|
| IPv4 | 행사장 전용 출구인지 확인 | |
| IPv6 | 실제 폰이 Google에 접속하는 경로 확인. 관리 가능한 행사장 범위만 허용 | |
| 이중 회선 | 두 출구를 모두 통제할 수 있을 때만 등록 | |
| CGNAT·공유 출구 | 행사장 고유 경계로 쓸 수 없으면 **직접 배포 보류** | |
| 유동 IP | 행사 직전 재확인, 종료 시 키 폐기 | |
| VPN·프록시 | 행사장 출구를 외부에 제공하는 기능을 운영상 차단 | |
| Wi-Fi→LTE 전환 | 신규 REST·Live와 기존 Live를 각각 시험(§3.2) | |
| 제한 변경 전파 | 콘솔 변경 직후 성공을 가정하지 않고 재검사 | |

외부 IP 확인 사이트 결과는 참고값이다. Gemini REST와 WebSocket이 같은 출구를 썼다는 증거로 쓰지 않는다. 브라우저의 온라인 상태·네트워크 변화 이벤트는 안내용이지 보안 근거가 아니다.

행사장 Wi-Fi 조건: 참석자 폰이 `https://generativelanguage.googleapis.com`(REST)과 `wss://generativelanguage.googleapis.com`(Live)에 직접 연결할 수 있어야 한다. 이 두 origin이 앱 CSP `connect-src`의 전부다. 게스트 Wi-Fi가 이를 막으면 공용 직접 경로를 쓸 수 없다.

## 3. 제한 시험 (§5.1 조건 3, §5.5 4)

`device-matrix.md` 절차 3·4와 같은 시험이며 결과는 그 문서의 표에 적는다. 시험용 폰 2대(행사장 Wi-Fi용, LTE용)와 행사별 QR을 준비한다.

### 3.1 내부·외부 신규 연결

| # | 위치 | 동작 | 기대 결과 |
|---|---|---|---|
| 1 | 행사장 Wi-Fi | QR 스캔 → 현장 공용 키 모드 → 설정 → 진단 → 텍스트 번역 검사 | 성공(REST 허용) |
| 2 | 행사장 Wi-Fi | 진단 → Live 목소리 검사 | 성공(WSS 신규 연결 허용) |
| 3 | 행사장 Wi-Fi | 진단 → 누르고 말하기 검사(STT) | 성공 |
| 4 | 외부(LTE·다른 회선) | 같은 QR → 텍스트 번역 검사 | 거부. 앱 표시는 `IP_DENIED`(확인된 경우) 또는 `PERMISSION_DENIED` |
| 5 | 외부 | Live 목소리 검사 | 거부. 브라우저에 HTTP 상세가 노출되지 않아 `LIVE_CONNECTION_FAILED`로 보일 수 있음(§7.5) |
| 6 | 양쪽 | 콘솔 변경 후 5~10분 뒤 1~5 재실행 | 동일 |

1·2·3 중 실패한 능력에는 공용 키를 배포하지 않는다. 4·5가 거부되지 않으면 IP 제한이 작동하지 않는 것이므로 **공용 직접 경로 전체를 보류**한다(§19).

### 3.2 기존 연결의 이동과 폐기

| # | 동작 | 기록 |
|---|---|---|
| 1 | 행사장 Wi-Fi에서 Live 목소리 재생 중 Wi-Fi 끄기(LTE 전환) | 기존 연결 유지 시간, 다음 턴 신규 연결 거부 여부 |
| 2 | 시험 키를 콘솔에서 폐기 | 신규 REST·Live 거부까지 걸린 시간, 재생 중이던 연결의 종료 여부 |
| 3 | 폐기 후 앱 "공용 이용 종료" | Live·마이크·오디오·메모리 키·임시 기록 정리 확인 |

이 결과는 §5.2의 한계를 참석자 안내에 정확히 반영하는 근거다. 즉시 차단을 약속하지 않는다.

## 4. QR 발급 (§5.4)

앱은 `#shared=` fragment로 공용 키를 받는다. **브라우저 앱은 QR·URL 생성기를 제공하지 않는다**(자격증명 URL 재생성 금지). 관리자가 오프라인 도구로 만든다.

형식: `https://<앱 origin>/#shared=` 뒤에 `encodeURIComponent(JSON.stringify(payload))`.

| payload 필드 | 필수 | 규칙 |
|---|---|---|
| `version` | 예 | 숫자 `1` |
| `providerId` | 예 | `"gemini"` |
| `eventName` | 예 | 행사명, 1~120자, 제어 문자 금지. 앱 상단과 설정에 "행사: …"로 표시 |
| `key` | 예 | 행사별 공용 키(출력 가능 ASCII 1~512자) |
| `expiresAt` | 아니오 | 앱 이용 종료 시각, Unix **밀리초**. 지나면 앱이 `SHARED_USE_ENDED`로 거부. 제공자 키 만료가 아니다 |

허용되지 않는 필드가 있거나 형식이 다르면 앱이 `INVALID_SHARED_PAYLOAD`로 거부한다. QR로 endpoint·모델·폴백 정책·허브 주소를 지정할 수 없다. fragment 전체 길이는 8192자 이하.

앱 동작(§5.4): 첫 부트스트랩이 fragment를 읽고 즉시 URL에서 제거한다. 키는 메모리에만 두며 새로고침·앱 종료 후 다시 스캔한다. 기존 개인 키가 있으면 개인 모드를 유지하고 공용 전환은 사용자가 선택한다. 앱은 관리자가 회선 제한을 설정했는지 검증하지 않는다(payload는 서명이 아니다).

게시·노출 주의:

- QR 인식 앱·클립보드·화면 캡처·브라우저 확장 프로그램으로 키가 노출될 수 있음을 스태프에게 고지한다.
- QR은 행사장 안에서만 게시하고 온라인 게시·사진 공유를 금지한다. 노출 시 즉시 폐기·재발급한다.
- 행사별 QR을 인쇄하고 종료 후 회수한다.
- `expiresAt`은 행사 종료 예정 시각으로 두면 참석자가 종료 후 자동으로 안내를 받는다.

## 5. 행사 시작

### 5.1 정원과 범위

- 공용 직접 연결 정원은 §3 통과와 **실제 행사 규모의 한도 시험**(§5.5 5~6) 결과로 정한다. P2 시작 시 오너에게 최대 동시 인원·동시 청취 언어 수·전체 예배 길이를 확인하기 전에는(§10.2) 소규모 시범 이용만 허용한다. 임의의 100명·60분을 목표로 쓰지 않는다.
- P1 공용 경로에서 쓸 수 있는 기능은 순차통역(텍스트·PTT)과 Live 목소리다. 동시통역은 P2 전까지 없다.
- 공용 한도는 프로젝트 기준으로 모든 참석자가 공유한다(§9.1). "개인 폰으로 10분 성공"은 "N명이 한 시간 사용 가능"의 증거가 아니다(§10.1).

### 5.2 참석자 안내 (§6.3, §10.1)

1. 행사장 Wi-Fi에 연결한다(LTE에서는 공용 키가 거부된다).
2. QR을 스캔한다. 앱 상단에 행사명과 "현장 공용 키 모드" 배지가 보이는지 확인한다.
3. 안내 문구(§1)와 "공용 프로젝트의 한도를 다른 참석자와 공유한다"는 점을 읽는다.
4. 개인 키가 있는 사람은 개인 키 사용을 기본으로 유지한다.
5. 이어폰을 사용하고, 화면을 켠 전경 상태를 유지한다. 잠금·백그라운드에서는 중단될 수 있다.
6. 텍스트 통역은 바로 쓸 수 있다. 음성 사용자는 설정 → 진단에서 마이크·재생 검사를 버튼으로 실행한다.
7. 새로고침·앱 종료 후에는 QR을 다시 스캔한다.

### 5.3 스태프 준비물

- 인쇄 QR(행사별), 백업 QR 1장(별도 키 아님, 같은 키), 관리자 콘솔 접근 권한, 시험용 폰 2대, 이 문서의 §6 장애 대응 표.

## 6. 행사 중 장애 대응

앱 오류 코드와 표시 문구는 `app/i18n/ko.json`의 `error.*`이며 자동 재시도 예산은 한 턴에 3회다(§9.3). 자동 전환·자동 유료 전환은 없다.

| 참석자 화면 | 앱 동작 | 관리자 조치 |
|---|---|---|
| `IP_DENIED` "허용된 행사장 회선에서 접속했는지 확인해 주세요" | 공용 연결 중단, Wi-Fi·관리자 안내 | 참석자가 행사장 Wi-Fi인지, LTE 우선 설정이 꺼졌는지 확인. 여러 명이 동시에 겪으면 출구 IP 변경 의심 → §2.2 재확인, 콘솔 IP 제한 갱신 후 §3.1 재검사 |
| `PERMISSION_DENIED` / `INVALID_KEY` | 자동 재시도 중단, 설정 안내 | 키가 폐기·변경됐는지, API 제한이 맞는지 확인. 폐기됐으면 새 키·새 QR |
| `RATE_LIMITED` "요청이 많아 잠시 기다리고 있어요" | 서버 재시도 정보와 지터를 둔 대기 | 동시 이용자 수를 줄이거나 발화 간격을 두도록 안내 |
| `DAILY_LIMIT` "번역 한도를 소진해…" | 반복 재시도 금지. 기존 내용 열람 가능 | §7 한도 소진 안내. 다른 공용 키를 자동 순환하지 않는다 |
| `UNKNOWN_429` "요청이 제한됐지만 원인과 재개 시각은 확인되지 않았어요" | 한 번 호출 후 자동 반복 중단 | 콘솔 사용량 확인. 소진이면 §7, 아니면 잠시 뒤 수동 재시도 안내 |
| `UNAVAILABLE` / 503 | 제한된 재시도와 등록된 모델 폴백(`gemini-3.1-flash-lite` → `gemini-3.5-flash`) | 지속되면 제공자 장애. 기기 음성·자막 이용 안내 |
| `LIVE_CONNECTION_FAILED` | 재연결은 §9.3 예산(최초 연결 외 최대 3회) 안에서만 시도하고 같은 문장을 자동 재전송하지 않음. 첫 오디오 전 실패면 기기 음성으로 한 번 폴백 | 외부 회선(LTE)인지 확인. 내부에서도 반복되면 §3.1 2번 재검사 |
| `VOICE_FAILED` "번역은 완료됐지만 음성을 만들지 못했어요" | 자막 유지, "기기 음성으로 다시 읽기" 버튼 제공. 자동 전체 재독 없음 | 기기 음성 사용 안내 |
| `SESSION_LIMIT` | 이전 연결 종료 확인 후 제한된 재연결 | 다른 탭·기기에서 같은 앱이 열려 있는지 확인 |
| `NETWORK_ERROR` / 오프라인 배지 | 셸은 남고 새 통역 불가 | Wi-Fi 상태 확인 |
| `SHARED_USE_ENDED` "공용 이용이 종료됐어요" | `expiresAt` 경과 또는 관리자 종료. 임시 기록 삭제 | 행사 연장 시 새 `expiresAt`으로 QR 재발급 |
| `INVALID_SHARED_PAYLOAD` | QR 거부 | QR 인쇄·인코딩 확인 후 재발급 |
| `SAFETY_BLOCKED` | 자동 재시도 없음, 모델 순환 없음 | 내용 문제이므로 조치 없음 |
| 마이크 거부·무음·재생 차단 | 권한 안내 / 입력 장치 점검 / 재생 버튼 | 텍스트 입력 또는 이어폰·마이크 위치 안내 |

모든 403을 IP 차단으로 해석하지 않는다(§7.5). 폰 화면의 오류 문구는 코드 문구만 보여 주며 제공자 원문·키는 포함하지 않는다.

## 7. 한도 소진 시 안내 (§9.4)

| 상태 | 남는 기능 |
|---|---|
| Live 목소리만 실패 | 새 REST 번역·기기 음성·자막 |
| REST 실패, 기존 번역 있음 | 기존 번역 보기·가능한 기기 음성 |
| 모든 번역 경로 실패 | 기존 기록 열람·입력 초안·키 설정 |
| 인터넷 없음 | 로컬 셸 |

금지·원칙:

- 공용 한도 소진 시 **다른 공용 키를 자동 순환하지 않는다**. 예비 키를 배포하려면 관리자가 새 QR을 발급하고, 이는 행사 기록에 남긴다.
- 개인 키 전환은 사용자의 명시적 선택으로만 한다. 앱은 자동 전환하지 않는다.
- 유료 자동 전환·새 유료 구독으로 해결하지 않는다(§19 "공용 무료 한도 부족" → 정원 축소·개인 키·허브).
- 한도 경계는 Gemini 프로젝트 기준이다. 키 교체를 한도 초기화로 취급하지 않는다(§9.1).

안내 문구 예: "공용 통역 한도가 소진되었습니다. 자막·기존 내용은 계속 볼 수 있고, 개인 Gemini 키가 있으면 설정에서 개인 키 모드로 바꿔 사용할 수 있습니다."

## 8. 행사 종료와 키 폐기 (§5.5 8~9)

| 단계 | 작업 |
|---|---|
| 1 | 참석자에게 설정 → "공용 이용 종료"를 누르도록 안내한다. Live·마이크·오디오·메모리 키·임시 기록이 정리된다 |
| 2 | 관리자가 **제공자 콘솔에서 행사 키를 폐기**한다. 앱에서 삭제하는 것과 콘솔 폐기는 다르다(§11.2) |
| 3 | 폐기 후 시험 폰에서 신규 REST·Live가 거부되는지, 열려 있던 연결이 어떻게 끝나는지 확인·기록한다(`device-matrix.md` 절차 4) |
| 4 | 인쇄 QR을 회수·폐기한다 |
| 5 | 콘솔에서 행사 중 사용량·오류율을 확인해 기록한다 |
| 6 | 결과를 §10 양식과 `device-matrix.md`에 남긴다. 실패·지연·한도 소진은 다음 행사 정원 결정의 입력이다 |

폐기 후에도 유동 IP·재할당된 출구를 통해 살아 있는 키는 보호되지 않으므로(§5.2) 폐기를 미루지 않는다.

## 9. 허브 운영 (§10.2~10.3, P2)

- 대규모 공용 이용은 언어별 한 세션을 공유하는 **맥 허브 방송**을 우선한다. 청중은 마이크·API 키 없이 듣는다.
- 허브 방식에서는 공용 키를 허브에만 보관하고 청중 브라우저에 배포하지 않는다.
- 허브는 행사 중에만 켜며 개인 앱의 필수 의존성이 아니다. 기존 허브의 모바일 지원은 P2 시험 전 미검증이다.
- 허브 접속 조건(§10.3): 행사장 네트워크에만 노출, 게스트 Wi-Fi의 기기 간 통신 차단 여부 확인, HTTPS/WSS 인증서·DNS·로컬 네트워크 접근 검증. 안전한 로컬 HTTPS를 기존 인프라로 만들 수 없으면 허브 기능을 보류한다.
- 허브 고장 시 청중 전원을 공용 Live에 자동 연결하지 않는다. 개인 키 이용자는 직접 모드로 전환하고, 나머지는 운영자가 대체 안내한다.

P1 앱에는 허브 어댑터·관리자 화면이 없다. 이 절은 P2에서 정원·운영 방식을 확정할 때 사용한다.

## 11. P2 현장 방송·규모 운영 절차 (P2-22 추가)

위 P1 절은 당시 절차·검증 이력이다. P2 청중 구현의 추가가 P1 공용 직접 경로의 미검증 상태를 해소하지 않는다. P2의 실제 지원 판정도 아직 미검증이다. 목표·시험 양식은 [규모 시험 문서](p2-capacity.md), 기기별 증거는 [기기 매트릭스](device-matrix.md)에 기록한다.

행사 전:

1. N_max, 직접/허브 인원, 언어별 인원, L_active, 전체 길이와 자막·음성 지연·실패·누락 허용치를 확정한다. 10분 예비 시험 후 최대 인원·전체 길이 실측까지 통과한 범위만 운영한다.
2. 현재 서버의 최대 3언어·150분 자동 종료를 준비 방송 시간까지 포함해 대조한다. 초과 요구는 시간·정원·재참가 절차를 조정하거나 운영을 보류한다. 재시작을 무중단 운영으로 안내하지 않는다.
3. 앱에 검토 등록된 허브와 릴리스 CSP, HTTPS/WSS 인증서·DNS·게스트 Wi-Fi 접근을 확인한다. 안전한 접속이 안 되면 현장 방송을 보류한다. 관리자 주소를 청중이 임의 입력하도록 우회하지 않는다.
4. 청중은 현장 방송을 선택하고 방 코드로 참가한다. 방 코드는 앱 메모리에만 두며, 명령행·보고서·스크린샷·일반 앱 URL에 넣지 않는다. 프로토콜상 참가 WebSocket URL에는 포함되므로 인증 URL 로깅도 피한다. 허브 제공자 키는 허브에만 보관한다.
5. hello는 참가 완료이며 방송 중 증거가 아니다. 실제 자막 수신을 확인한다. 최근 자막은 자동 낭독하지 않는다. 청중이 소리를 켠 뒤 새 확정 자막의 기기 음성을 확인한다. 이어폰·ko/en/ja 지원 음성과 음량을 각 기기에서 점검한다. 기기 TTS의 외부 처리 여부를 오프라인이라고 단정하지 않는다.
6. 허브 CPU·메모리·LAN·송신 대기와 AP 상태의 관측 담당자 및 중단 기준을 정한다. 현 서버에는 명시적인 느린 청중 송신 버퍼 상한이 없다. 클라이언트 큐 상한 통과만으로 현장 안전을 승인하지 않는다.

| 상황 | 조치·재개 조건 | 남길 증거 |
|---|---|---|
| 느린 청중·지연/음성 생략 | 해당 기기 음소거·네트워크 확인. 자막 수신을 유지하고 실제 누락과 음성 생략을 구분 | 기기 ID, 큐·생략·복구·다른 청중 영향 |
| 허브 RSS·송신 대기 지속 증가 | 확정 중단 기준에 따라 참가 제한·정원 축소 또는 방송 중지. 승인 범위 재시험 | 인원·언어·경과 시간·메모리 추이·조치 |
| 단절·재접속 | 제한된 자동 복구 후 실패하면 수동 재접속. 최근 최대 30개는 완전 복구가 아님. 불확실한 방송 전환은 음소거하고 사용자 재개 | 복구 시간·시도 횟수·누락 가능·중복 낭독 여부 |
| 150분 자동 종료·cast.stopped | 자동 재참가하지 않음. 방송 재개 시 새 참가 후 소리를 수동으로 켬 | 실제 종료 시각·중단 길이·재참가 결과 |
| 허브 전체 장애 | 전 청중을 공용 Live로 자동 전환하지 않음. 개인 직접 모드는 사용자 선택, 나머지는 운영자가 대체 안내 | 장애 범위·대체 운영·한도 영향 |
| 기기 음성 없음·재생 실패 | 자막 청취 유지, 음성 지원 기기 확인. 제공자 voice 자동 호출 없음 | 언어·OS·음성 지원·실패 코드 |
| 백그라운드·잠금·pagehide·입력 종료 | 작업 중지 확인. 복귀 후 사용자가 시작하며 과거 입력·음성을 자동 재전송하지 않음 | 중지/복귀·마이크·소켓·재생 종료 |
| close 확인 실패 | 새 연결로 넘어가지 않고 해당 기기 중단. 종료 확인 후 수동 재개 | 안전한 오류 코드·점유 상태·업데이트 보류 |
| quota·일일 소진·원인 불명 429 | 기존 오류 정책에 따라 중지·콘솔 확인. 키·모델 순환으로 우회하지 않음 | 코드·분모·콘솔 집계, 원문 오류 제외 |

종료 시 방송 중지와 청중 나가기를 확인하고 TTS·소켓·재시도·임시 자막이 정리되는지 점검한다. 공용 직접 키를 사용했다면 기존 §8의 콘솔 폐기를 별도로 수행한다. 방 코드·키·원문·번역문·오디오는 결과에 남기지 않는다.
