# 기기·환경 검증 매트릭스 (P1-21·P2-23)

기준 설계: `design-v0.6.md` §4.2, §13, §16(P1 완료 기준), §17, §19. 이 문서는 **구현 완료**와 **실제 지원 범위**를 분리해 기록한다. 자동 테스트나 헤드리스 브라우저 통과를 실기기·실키·행사장 합격으로 확대하지 않는다(§16, §17.4).

P1 §1~7은 당시 기록을 보존한다. P2 현재 지원 판정은 §9와 [P2 실기기 결과](p2-device-results.md)를 따른다.

## 5. 알려진 문제·제한

| 항목 | 내용 | 영향 |
|---|---|---|
| iOS 홈 화면 앱 마이크 | §13.3: WebKit의 홈 화면 앱 마이크 이력 때문에 계속 미검증으로 취급 | E5·E6 음성 기능은 시험 통과 전 지원 범위 밖 |
| 전경 동작 기준 | §13.3: 화면이 켜진 전경 상태가 기준. 잠금·백그라운드 지속 녹음은 보장하지 않음 | 모든 기기 |
| JSON 모듈 import | `app/main.js:16`이 부팅 실패 안내용 영어 사전을 `import ... with { type: 'json' }`으로 읽는다. Chrome 152 부팅으로 동작 확인. Safari·이전 iOS의 지원과 배포 호스트의 `.json` MIME(`application/json`)은 실기기·배포 후 확인 필요. 미지원이면 모듈 그래프 전체가 실행되지 않는다 | E4·E5·E6 |
| PTT 진단의 범위 | 설정의 "누르고 말하기 검사"는 마이크 캡처 + 독립 STT 검사다. 실제 순차 PTT(결합 WAV 번역 1회)와 음성 출력은 별도 시험이 필요하다(P1-20b) | 절차 1 |
| 이전 릴리스 캐시 | 서비스 워커가 이전 릴리스 캐시를 삭제하지 않는다. 수거 정책은 미정 | 장기 사용 저장 공간 |
| 다중 탭 조정 | 창 수 확인은 최선 노력이며 다른 브라우저·기기의 Live 수를 강제하지 않는다(§9.1) | 업데이트·Live 1개 정책 |
| 설치 앱 이름 | UI 언어를 바꿔도 설치된 앱 이름이 즉시 바뀌지 않을 수 있다(§12) | E3·E5 |
| 이용 조건 | `GEMINI_DEFINITION.terms.status`가 `unreviewed`, `reviewedAt` null. 공개 대상 확정 전(§11.4) | 절차 6 |
| 실제 API 응답 | 모든 제공자 시험은 모의 응답이다. 실제 모델(`gemini-3.1-flash-lite`, 폴백 `gemini-3.5-flash`, 목소리 `gemini-3.1-flash-live-preview`)의 응답·한도는 미확인 | 절차 1~4 |

## 7. 브라우저 수동 절차와 기록 양식

각 절차는 HTTPS 배포 또는 신뢰된 개발 HTTPS에서 수행한다(§13.1). 폰에서 맥의 HTTP LAN 주소로 마이크를 판정하지 않는다. 시험 전 릴리스 ID(설정 → 앱 → 버전)와 기기·OS·브라우저 버전을 적는다.

### 절차 1. 6방향 × 10발화 실키 시험 (Android Chrome · iPhone Safari, HTTPS)

1. 개인 키를 입력하고(저장 선택 없이) 개인 키 모드를 선택한다. 설정 → 진단에서 텍스트 번역 검사를 먼저 통과시킨다.
2. 언어쌍 ko→ja, ja→ko, ko→en, en→ko, en→ja, ja→en 순으로 각 10발화를 PTT로 시험한다. 숫자·고유명사·부정문·명령형 문장을 섞는다(§17.3).
3. 모든 턴이 결과·무음·오류·취소 중 하나로 끝나는지, 중복 표시·중복 재생·취소 후 재생이 없는지 확인한다.
4. 따뜻한 세션에서 PTT 종료→실제 첫소리 p50 3초 이하를 목표로 측정한다. p95·최대·차가운 시작·실패율·표본 수를 함께 적는다. 목표 미달이면 "성능 목표 미달"과 지원 조건을 적는다.
5. 텍스트 입력 경로로도 각 방향 1회 이상 확인한다.

### 절차 2. 설치 후 캡처·재생·중단·복귀·업데이트 시험

1. Android Chrome: 설정 → 앱 → "앱 설치" 또는 브라우저 메뉴로 설치. iPhone: Safari 공유 → 홈 화면에 추가.
2. 설치 앱에서 마이크 검사·재생 검사·PTT 1회·Live 목소리 검사·기기 음성 재생을 순서대로 실행한다.

### 절차 3. 행사장 내부/외부의 REST·Live 목소리 신규 연결 시험

`venue-runbook.md` §3의 제한 시험과 같은 절차다. 행사별 공용 키를 IP·API 제한한 뒤:

1. 행사장 Wi-Fi에서 QR 스캔 → 공용 모드 → 텍스트 번역 검사(REST) 통과.
2. 같은 자리에서 Live 목소리 검사(WSS 신규 연결) 통과.
3. 행사장 밖(LTE 또는 다른 회선)에서 같은 QR → 텍스트 번역 검사가 `IP_DENIED`(확인된 경우) 또는 `PERMISSION_DENIED`로 거부.
4. 밖에서 Live 목소리 검사가 거부(브라우저에는 `LIVE_CONNECTION_FAILED`로 보일 수 있음, §7.5).
5. 콘솔 변경 직후 성공을 가정하지 않고 몇 분 뒤 재검사한다(§5.3).

### 절차 4. 기존 연결의 Wi-Fi→LTE 이동과 키 폐기 동작

1. 행사장 Wi-Fi에서 Live 목소리 재생 중 Wi-Fi를 끈다. 기존 연결이 얼마나 유지되는지, 다음 턴의 신규 연결이 거부되는지 기록한다. 즉시 차단은 보장하지 않는다(§5.2).
2. 관리자가 제공자 콘솔에서 키를 폐기한 뒤: 신규 REST·Live 거부 시각, 재생 중이던 연결의 종료 여부와 시각을 기록한다.
3. 앱의 "공용 이용 종료"가 Live·마이크·오디오·메모리 키·임시 기록을 정리하는지 확인한다(§6.3).
