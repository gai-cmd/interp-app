# P3 검증 기준과 원장

기준: [design-p3.md](design-p3.md) §1·§2(오케스트레이터 필수 실검증)·§4, [DESIGN.md](DESIGN.md) §9, [design-v0.6.md](design-v0.6.md) §17·§19, [release-checklist.md](release-checklist.md). 이 문서는 P3-01이 만들고 P3-12·17·38·39가 과제 ID 절을 **추가**한다. 이전 절의 미검증 표시는 지우지 않는다.

## 1. 판정 원칙

- **자동 검사 통과 ≠ 수동 완료.** G 세 명령과 `node --test tests/`는 구현 회귀의 증거다. 화면 배치·실기기·실키·배포·규모 판정은 §3의 수동 항목에 실제 증거(환경·릴리스·일시·담당·관측)가 붙어야 바뀐다.
- 증거가 없는 칸은 `미검증`으로 둔다. 미측정을 성공·비해당·0으로 바꾸지 않는다. 실패는 지우지 않고 재시험 회차를 잇는다.
- Node 테스트의 모의 DOM·CSS 문자열 검사는 실제 레이아웃·대비·터치 영역 실측을 대신하지 않는다. `_headers` 검사 통과는 GitHub Pages의 실제 응답 헤더 적용 증거가 아니다.
- 허브 서버가 `policy.control` 확장을 보내기 전에는 허브 실시간 통제를 fixture 검증까지만 완료로 표시한다.
- P2에서 보류된 항목(§4)은 P3 자동 검사가 아무리 통과해도 보류 상태를 유지한다. 해제는 해당 P2 문서의 증거표에 실측이 채워질 때만 가능하다.
- 키·방 코드·QR payload·인증 URL·발화 원문·원본 오디오는 증거에 넣지 않는다. 비밀을 제거한 집계와 참조 ID만 남긴다.

## 2. 자동 검사

| 검사 | 명령 | 범위 |
|---|---|---|
| 전체 회귀 | `node --test tests/*.test.mjs` | 모든 과제 |
| 디렉터리 진입 | `node --test tests/` | 모든 과제(P1-20b 이후 `tests/package.json` 덕분에 동작) |
| 사전 완전성 | `node scripts/check-i18n.mjs` | 세 언어 키 집합·placeholder·사용 키·동적 열거 키(P3-32부터 `admin/*.html`·`app/admin/` 포함) |
| 공백 | `git diff --check` | 모든 과제 |
| 릴리스 포장 | `node scripts/stage-release.mjs --id <id> --out <임시경로>` → `node scripts/check-release.mjs <임시경로>` | P3-13·35·36 및 정책·관리자·SW 변경 과제. 산출물은 검사 후 삭제 |
| 과제별 지정 검사 | design-p3.md §2의 각 과제 "완료 확인 명령" | 해당 과제 |

각 과제 보고서는 위 명령을 **직접 실행한 출력**(통과 수, 실패·취소·skip·todo 0, I18N_OK의 키 수)을 적는다. 기존 테스트 기대값을 바꿨으면 파일·단언·이유를 적는다. 삭제·skip으로 우회하지 않는다.

| 명령 | 결과 |
|---|---|
| `node --test tests/*.test.mjs` | 607 통과, 실패·취소·skip·todo 0 |
| `node --test tests/` | 내부 606개 + 디렉터리 진입 1개 통과 |

P3-01은 코드를 바꾸지 않았으므로 위 수치는 P3-00 직후 기준선과 같다. 이 결과는 문서 완료 확인이며 §3·§4의 어떤 수동 항목도 해제하지 않는다.

## 5. 과제 절 추가 양식

P3-12·17·38·39는 아래 양식으로 이 문서 끝에 절을 추가한다.

```markdown
## P3-NN <제목> (YYYY-MM-DD)

- 자동: <실행 명령과 출력 요약>
- 수동 항목 갱신: V## 행에 "구현 완료·미검증" 또는 증거 첨부 판정
- 바꾼 기존 단언: <파일·단언·이유> 또는 없음
- 남은 미검증: <목록>
```

P3-39는 §3 전체를 최종 표로 정리하되, 증거 없는 행은 그대로 `미검증`으로 남긴다.
