## 증거 입력 규칙

오너는 키를 시험 기기의 브라우저에 직접 입력한다. 실키·방 코드·QR payload·인증 URL·헤더·제공자 원문 오류를 명령 인자, fixture, 문서, 로그, 오류 객체에 넣지 않는다. 기본 결과에는 발화 원문·번역문·원본 오디오도 넣지 않는다. 증거는 비밀을 제거한 집계와 참조 ID로 전달한다. 기존 Live 인증 소켓 URL과 허브 참가 소켓 URL의 전달 경계는 유지하며 모든 네트워크 URL에 비밀이 없다고 주장하지 않는다.

각 실행은 아래 환경 ID와 회차 ID를 연결한다. 기기 모델, OS·브라우저 정확한 버전, 웹/설치 방식, 앱 릴리스·소스 리비전, 시험일·담당, 실제 선택 모델, 음성 설정·기기 TTS 엔진/음성, 이어폰 종류, 실제 입력 샘플레이트, 좌석·AP/회선의 비밀 없는 식별자, IPv4/IPv6 조건, 경로·목표어를 기록한다. 허브는 서버 리비전과 방송 측 실제 모델도 필요하다. 설정 후보 모델과 실제 실행 모델을 구분한다.

행별로 계획 표본과 실제 표본 수/분모, 관측 결과, 근거 위치, 실패 코드, 제한·재시험 회차를 적는다. 미실행은 `미검증 — 입력 대기`, 실제 실패는 실패, 기능 부재는 근거를 붙여 미지원으로 기록한다. 미측정을 성공이나 비해당으로 바꾸지 않는다. 환경·릴리스·모델이 달라지면 별도 행으로 남긴다.

| 환경 ID | 기기 | OS·버전 | 브라우저·버전 | 실행 형태 | 시험 릴리스 | 시험일·담당·근거 | 결과 |

## P3-00 오너 연속성·키 저장 재시험

2026-09-06 구현 후 시험 항목이다. 아래 결과는 모두 **실기기 미검증**이며 기존 P2 판정을 대체하지 않는다. 자동 회귀·값 변경 근거는 [P3-00 보고서](p3-00-review.md)에 기록했다.

1. 개인 폰에서 최신 릴리스를 확인하고 이어폰을 연결한다. 설정에서 개인 키를 입력한다. 기본 체크 상태와 바로 옆 공용 기기 경고를 확인한다. 저장 후 키 섹션의 “키를 이 브라우저에 저장했습니다”와 저장 상태 배지를 확인하고 새로고침해 개인 키 모드가 유지되는지 본다. 키 값이 입력창에 다시 표시되어서는 안 된다.
2. 체크를 해제하고 다시 저장한다. “이번 실행 동안만 보관합니다 — 새로고침하면 다시 입력”과 메모리 상태를 확인한다. 새로고침 뒤 키 없음이어야 한다. 빈 값·공백 포함 형식 오류는 키 섹션 오류, 저장소 차단 환경은 저장소 실패 문구 또는 저장 옵션 미제공·메모리 보관 문구를 확인한다. 실제 키 값이 보이는 화면은 녹화하지 않는다.
3. 한국어→일본어, 설정의 동시통역 모델을 3.5로 선택하고 시작한다. “오늘 우리는 서울에서 출발해서 부산으로 갑니다. 기차는 오전 아홉 시 삼십 분에 출발하고, 표는 세 장을 샀습니다. 도착하면 김민수 씨를 만나서 함께 점심을 먹겠습니다.”를 약 20초 동안 자연스럽게 말한다. 전체 발화가 끝나기 전에 번역 음성이 나오고 미확정 자막이 표시되는지 본다. 자막은 같은 행에서 확정으로 바뀌어야 한다.
4. 같은 문장을 “오늘 우리는 서울에서 출발해서” / “부산으로 갑니다” / “기차는 오전 아홉 시 삼십 분에 출발합니다”처럼 구 사이 약 300~500ms 쉬며 말한다. 전체 종료까지 기다리는지, 첫 음절·숫자·고유명사가 잘리는지 기록한다. 이어서 긴 무침묵 발화도 비교한다. 짧은 침묵 시험만 통과했다고 지속 동시통역 합격으로 보지 않는다.
5. 설정의 진단에서 첫 오디오 수신·첫 예약·발화 시작 대비 첫 수신·발화 종료 대비 첫 수신 값을 기록한다. 음수는 추정 종료 전 수신을 뜻하며 물리적 청취 시각이 아니다. 별도 기기의 영상/녹음으로 발화 시작·끝, 화면 첫 partial, 이어폰 첫소리를 비교한다. 출력이 막히거나 음소거이면 첫 예약은 미측정일 수 있다.
6. 모델을 3.1 Flash로 바꾼다. 통역이 중지되고 자동 시작하지 않는지 확인한 뒤 시작해 동일 문장·마이크 거리·회선으로 반복한다. 각 모델 5회 이상, 일본어→한국어도 반복한다. 폴백이 발생한 실행은 선택한 모델의 성능 표본으로 섞지 않는다. 키·권한·한도 오류를 속도 차이로 해석하지 않는다.
