# v0.6 설계

- 기준일: 2026-09-05.
- 상태: **오너 결정 반영 완료된 구현 기준 설계**. 실키·실기기 시험 완료를 뜻하지 않는다.

- 기본 구조: 스마트폰 → Gemini 직접 연결. 선택적 행사장 맥 허브.
- 배포: HTTPS 웹 + 홈 화면 바로가기/PWA 설치만.
- 비용: 무료 이용 범위와 기존 인프라. 유료 자동 전환 없음.
- 구현 위치: `~/jarvis2/interp-app/`.
- 실행 환경: 빌드 도구 없는 ES 모듈·정적 파일. 테스트는 Node 24의 `node --test`.

## 1. 취지와 변경하지 않는 결정

1. 오브 통역 창을 독립 웹 앱으로 만든다. 개인 맥·오브 설치 없이 스마트폰에서 실행한다.
2. 자체 백엔드를 상시 운영하지 않는다. 정적 호스팅·외부 API·인터넷 연결은 필요하다.
3. 개인 키 사용을 기본으로 한다. P1에서는 본인 Gemini 프로젝트의 키를 사용하며 사용량·결제 상태는 사용자가 확인한다.
4. 공용 키는 **검증된 행사장 공인 출구 IP 제한**으로 운영한다. 개인 키에는 장소 제한을 요구하지 않는다.
5. 공인 IP 제한은 행사장 회선을 통한 접근 제한이다. 물리적 위치나 외부 사용의 절대 차단을 보장하지 않는다. 오너가 이 운영 경계를 승인했다.
6. 한국어·영어·일본어 UI를 P1부터 제공한다.
7. 설치 없이 웹에서 시작하고, 홈 화면 추가/PWA 설치를 제공한다.
8. 스토어 등록과 Android APK 사이드로드는 현재 범위에서 제외한다.
9. 새 유료 구독·유료 중계·종량제 자동 전환을 도입하지 않는다.
10. 설교에서는 행사 중 기존 맥 허브를 켜는 운영을 허용한다. 개인 앱은 허브 없이 작동해야 한다.
11. 주요 사용처는 설교 청취, 대면 통역, 별도 전화기 기반 전화 통역 보조, 여행 회화다.
12. 다른 API 제공자를 추가할 구조는 마련하되, 실제 지원·이용 조건을 검증하기 전 사용 가능하다고 표시하지 않는다.

## 4. 전체 구조와 지원 범위

### 4.1 기본 구조

```text
정적 HTTPS 호스팅
  └─ HTML / CSS / ES 모듈 / i18n / manifest / service worker
                         ↓
스마트폰
  ├─ UI·상태·키 보관·임시 기록
  ├─ 마이크·リ샘플링·오디오 재생
  └─ 능력 라우터
       ├─ 브라우저 직접 호출 허용 → 제공자 API
       └─ 허브 전용 → 검증된 현장 HTTPS/WSS 허브 → 제공자 API
```

P1은 Gemini 직접 연결만 구현한다. 허브 전용 경로는 능력 표와 라우팅 차단까지 구현하고, 실제 허브 어댑터는 P2 이후 해당 제공자 도입 시 구현한다.

정적 호스트에 API 키·음성·통역문을 전송하지 않는다. 정적 파일 접속 정보는 호스트가 처리할 수 있다.

음성·텍스트·인증 정보는 선택한 API 제공자에게 전달된다. 허브 중계에서는 허브도 해당 데이터를 처리한다. 설정과 첫 실행 안내에 실제 처리 주체를 표시한다.

### 4.2 지원 범위

| 시나리오 | 제공 방식 | 단계·제한 |

## 5. 공용 키의 공간 제한과 관리자 운영

### 5.1 보장하려는 경계

공용 키 직접 배포는 다음 조건을 모두 만족할 때만 활성화한다.

1. 행사별 키에 관리 가능한 행사장 출구 IP 제한을 설정한다.
2. 제공자의 해당 API만 허용하는 제한을 적용한다.
3. 사용하려는 능력의 실제 REST·WebSocket 경로에서 내부 허용·외부 거부를 확인한다.
4. 행사 종료 후 제공자 콘솔에서 키를 폐기한다.
5. 실제 제한 동작을 확인하지 못한 기능에는 공용 키를 배포하지 않는다.

P1 제공자는 Gemini다. 향후 제공자가 동등한 제한을 제공한다고 가정하지 않는다. 제한을 충족하지 못하는 제공자의 공용 원본 키 직접 배포는 금지하고, 검증된 허브 경로만 검토한다.

**운영 기준은 승인되었다. 남은 조건은 행사·제공자·능력별 검증이다.**

### 5.2 보장하지 못하는 것

다음은 보장하지 않는다.

- 행사장 VPN·프록시·원격제어를 통한 외부 이용 차단.
- 동일 공인 출구를 공유하는 모든 외부 이용자 구별.
- Wi-Fi 전파가 건물 밖으로 나가는 경우의 위치 제한.
- 출구 IP 재할당 후 살아 있는 키의 보호.
- 이미 열린 Live 연결의 네트워크 이동 직후 차단.
- 복사한 키의 별도 클라이언트 사용 방지.
- 자막·음성의 외부 재전송 방지.

사용자 문구는 다음 의미로 통일한다.

> 이 공용 키는 검증된 행사장 회선에서 사용하도록 제한됩니다. 물리적 위치를 확인하는 기능은 아니며, 이미 열린 연결의 즉시 차단을 보장하지 않습니다.

이 한계 자체는 출시 보류 사유가 아니다. 선언한 회선 제한이 실제로 작동하지 않으면 해당 공용 직접 경로를 보류한다.

### 5.4 키 배포 방식

기본은 **행사별 URL fragment QR + 메모리 보관**이다.

- payload는 버전, `providerId`, 행사명, 키, 선택적 이용 종료 시각을 포함한다.
- 초기 부트스트랩이 fragment를 먼저 읽고 즉시 `history.replaceState`로 제거한다.
- 길이·형식·등록 제공자·공용 직접 배포 허용 여부를 검사한다.
- QR에는 API endpoint·모델·폴백 정책·허브 주소를 지정할 권한을 주지 않는다.
- payload는 관리자 신원을 증명하는 서명이 아니다. 앱이 회선 제한 설정을 검증했다고 표시하지 않는다.
- 키와 원본 payload는 메모리에만 둔다. URL 재생성·로그·저장소·오류 원문에 남기지 않는다.
- 새로고침·앱 종료 후 다시 스캔한다.
- 기존 개인 키가 있으면 개인 모드를 유지한다. 공용 전환은 사용자가 선택한다.
- 종료 시각은 정상 앱의 이용 정책이다. 제공자 키 자체의 만료가 아니다.
- QR 인식 앱·클립보드·캡처·확장 프로그램을 통한 노출 가능성을 관리자에게 고지한다.

선택적 허브 키 전달은 검증된 HTTPS 환경에서만 허용한다. 응답은 `no-store`, 로그·URL에 키를 남기지 않으며, 방 종료와 원본 키 폐기를 구분한다.

**허브 전용 제공자는 원본 키를 청중 브라우저에 배포하지 않는다.** 관리자가 허브에서 키를 등록하고, 브라우저는 허브의 자격증명 참조 또는 방송 참가 정보만 사용한다.

Live 임시 토큰은 P1 필수 경로에서 제외한다. 토큰 도입 시 발급 주체·대상 능력·회선 제한 상속 여부를 별도로 검증한다.

## 6. 사용자 흐름

### 6.1 공통 첫 실행

1. 링크 또는 QR로 접속한다.
2. 공용 fragment가 있으면 먼저 회수·제거하고 검증한다.
3. `navigator.languages`에서 ko/en/ja를 선택하고, 미지원 언어는 영어로 표시한다.
4. 첫 화면에서 표시 언어를 변경할 수 있다.
5. 개인 키 설정 또는 현장 공용 모드를 선택한다.
6. 실제 제공자와 데이터 처리 안내를 확인한다.
7. 텍스트 통역은 마이크 검사 없이 시작할 수 있다.
8. 음성 사용자는 버튼을 눌러 입력 레벨·캡처·재생을 검사한다.
9. 첫 통역 성공 후 홈 화면 추가/PWA 설치를 안내한다.

P1에서는 순차통역을 제공한다. 동시통역은 P2 구현 전 실행할 수 없으며, 준비되지 않은 기능에 키 검사나 마이크 권한을 요구하지 않는다.

### 6.2 개인 키 모드

- P1에서는 Gemini 키 입력을 바로 보여 준다. 제공자 선택 단계를 추가하지 않는다.
- 기본 보관 위치는 메모리다. 개인 키만 선택적으로 기기에 저장한다.
- 제공자·키 출처별로 검사 결과를 구분한다.
- 검사는 실제 기능별로 실행한다. 텍스트 번역 성공을 PTT·Live 성공으로 확대하지 않는다.
- 음성 진단은 사용자가 시작한다. 모든 키 입력마다 자동 Live 연결을 만들지 않는다.
- 제공자 변경은 활성 요청·세션을 종료한 뒤 적용한다.
- 결제 활성화를 키 생성의 필수 단계로 안내하지 않는다.
- 정확한 결제 상태·프로젝트 전체 잔여량은 키 문자열만으로 확정하지 않는다.

## 7. 화면 명세

### 7.1 공통 셸

상단에 앱 이름, 제공자·키 출처 배지, 연결 상태, 설정 버튼을 둔다. 키 값은 표시하지 않는다.

최종 주 탭은 순차통역·동시통역이다. P1에서는 순차통역을 활성화하고 동시통역은 P2 준비 상태로 표시한다.

키·제공자·통역 언어·모드 변경이 활성 작업을 종료할 때 결과를 알린다. 변경 전 응답이 새 화면에 반영되지 않도록 세대 번호를 갱신한다.

| 음성 | 제공자 목소리 / 기기 음성 / 끔 |

| 진단 | 텍스트 번역·PTT·Live 목소리·동시통역을 각각 검사 |
| 기록 | P1은 저장 OFF·현재 내용 지우기. P3부터 저장·내보내기·전체 삭제 |
| 앱 | 웹/홈 화면 실행 형태, 버전, 설치·업데이트 안내 |
| 이용 안내 | 제공자별 데이터 처리·무료 한도·지원 조건 |

내부 키 주소는 `(providerId, keySource)`로 구분한다. 다른 제공자의 입력란이나 연결 검사에 키를 재사용하지 않는다.

능력 표의 상태는 `미구현 / 미검사 / 사용 가능 / 실패 / 현장 허브 필요`를 구분한다. 등록되었다는 이유만으로 사용 가능 표시를 하지 않는다.

허브 전용 제공자의 브라우저 키 입력은 비활성화하고 **“현장 허브에서 키 등록”**을 표시한다. 향후 설정 컴포넌트를 허브 관리자 화면에서 재사용할 수 있으나, P1에 관리자 화면은 구현하지 않는다.

고급 능력별 제공자 선택과 제공자 간 폴백 설정은 실제 복수 제공자를 등록한 뒤 노출한다. 자유 페르소나는 제외한다. 미리듣기는 사용자가 누를 때만 실행한다.

## 8. 엔진과 폴백 사다리

### 8.1 공통 엔진 규약

- UI는 제공자 endpoint·요청 필드·키 전달 방식을 알지 않는다.
- UI → 통역 엔진 → 능력 라우터 → 제공자 어댑터 순으로 호출한다.
- 네 능력과 등록 계약은 §20에 따른다.
- `turnId`, `sessionId`, 연결 세대 번호, `AbortSignal`을 전달한다.
- 취소·키 삭제·모드 변경 후 늦은 응답과 오디오는 폐기한다.
- 재시도는 공통 실행기가 관리한다. 어댑터 내부에 숨은 재시도 루프를 두지 않는다.
- 제공자별 모델·지원 필드·endpoint·오류 해석을 해당 제공자 디렉터리에 모은다.
- Gemini REST는 지원되는 키 헤더를 사용하고, Live 인증 URL은 로그·진단에 남기지 않는다.
- 모듈 import만으로 브라우저 전역·마이크·WebSocket을 실행하지 않는다. 환경 객체는 생성 시 주입한다.

### 8.2 순차통역과 STT

P1 경로는 다음과 같다.

```text
텍스트 ──────────────────────┐
                             ↓
PTT → PCM → WAV → Gemini translate
                     └─ 음성 입력이면 원문 전사와 번역을 함께 반환
                             ↓
                    결과 검증·확정 자막
                             ↓
                         목소리 출력
```

`translate`는 텍스트 입력을 필수로 지원하고, 제공자가 선언한 경우 음성 입력을 지원한다. Gemini P1은 **음성 전사+번역 결합 요청**을 구현해 PTT마다 STT와 번역을 따로 호출하지 않는다.

`stt`는 별도 능력으로 구현한다. 원문 전사만 필요한 요청과 향후 음성 입력을 지원하지 않는 번역 제공자 조합을 위한 계약이다. P1 일반 PTT는 이 별도 경로를 중복 호출하지 않는다.

번역 기본·품질 폴백 모델은 오너 제공 기준을 적용한다.

1. `gemini-3.1-flash-lite`, 지원 설정에서 thinking 0.
2. 품질 검증 실패 또는 적용 가능한 모델 오류 시 `gemini-3.5-flash`.

기존 `translate.js`는 텍스트 입력·문자 종류 검사·여러 모델 및 설정 변형 재시도를 포함한다. 그대로 복사해 완료 처리하지 않는다.

브라우저 이식에서 추가·변경할 사항:

- 음성 WAV 입력과 원문 전사 필드.
- 구조화된 결과: 원문, 번역문, 감지 언어, 결과 상태.
- 무음·인식 불가를 정상적인 별도 결과로 표현.
- 숫자·고유명사·혼합 언어를 문자 종류만으로 거부하지 않는 검증.
- 알 수 없는 모델 별칭의 자동 순환 제거.
- 설정 미지원 후 재호출도 총 시도 예산에 포함.
- 원문·프롬프트 경계 분리.
- 입력 오디오·응답 크기와 요청 시간의 상한.
- `AbortSignal` 전파.

언어·JSON 검증 통과를 의미 정확성 보장으로 표시하지 않는다. 기존 결과와의 동등성 검사는 재사용 동작을 확인하는 절차이며, 기존 약한 검증까지 보존하는 조건은 아니다.

## 9. 한도·429·503·세션 관리

### 9.1 기본 정책

- 앱 인스턴스 전체에서 활성 Live 소켓은 기본 1개다. 제공자가 달라도 합산한다.
- 순차 목소리·동시통역·미리듣기를 동시에 열지 않는다.
- 이전 연결 종료가 확인되기 전 새 연결을 열지 않는다. 종료 확인 실패 시 세션 교체를 중단한다.
- 같은 origin의 탭 간 조정은 최선 노력이며 전역 강제 보장이 아니다.
- 제공자 오류는 공통 오류 분류로 정규화한다.
- 한도 경계는 제공자별 선언에 따른다. Gemini는 프로젝트 기준이며, 다른 제공자에 이를 일반화하지 않는다.
- 키 교체를 한도 초기화로 취급하지 않는다.
- 전체 잔여량을 모르면 관측한 호출 수·연결 시간·오류만 표시한다.

### 9.3 재시도 예산

초기 정책은 다음과 같다.

| 작업 | 자동 시도 예산 |
|---|---|
| 한 번의 순차 번역 작업 | STT·번역·모델 폴백·설정 변경·재시도를 모두 합쳐 최대 3회 |
| 번역 품질 캐스케이드 | 서로 다른 번역 모델 최대 2개, 위 3회 안에서 실행 |

Live 재연결은 약 1·2·4초에 지터를 적용하되 서버의 더 긴 대기를 우선한다. 실패 횟수는 소켓이 잠깐 열렸다는 이유만으로 초기화하지 않는다. 사용자 재시작 또는 60초 안정 동작을 초기화 기준의 설계값으로 둔다.

목소리는 일부 오디오를 받은 뒤 자동으로 전체 문장을 다시 읽지 않는다. 남은 음성 실패를 표시하고 기기 음성 재생을 사용자가 선택하게 한다. 첫 오디오 이전 실패에는 기기 음성 폴백을 적용할 수 있다.

실패·취소·시간 초과는 모두 종료 상태에 도달한다. 타이머와 재시도 작업도 함께 정리한다.

### 10.2 기존 현장 허브 사용

오너는 설교 중 기존 맥 허브 운영을 승인했다.

```text
믹서·강단 입력 → 행사 중 맥 허브
                  ├─ 언어 A 통역 → A 청중
                  ├─ 언어 B 통역 → B 청중
                  └─ 언어 C 통역 → C 청중
```

- 개인 이용은 개인 키 직접 연결을 기본으로 한다.
- 대규모 공용 이용은 언어별 한 세션을 공유하는 허브 방송을 우선한다.
- 청중은 마이크·API 키 없이 방송을 들을 수 있다.
- 공용 키는 허브에만 보관할 수 있다.
- 허브가 세션·정원·종료를 중앙 제어한다.
- 허브의 LAN 전송량은 청중 수에 따라 증가한다.
- 허브는 행사 중에만 켠다. 독립 개인 앱의 필수 의존성이 아니다.
- 기존 허브의 모바일 지원은 P2 시험 전 미검증이다.

**P2 시작 시** 오너에게 최대 동시 인원, 동시 청취 언어 수, 전체 예배 길이를 확인한다. 그 수치로 직접 연결과 허브 방식의 용량 시험을 정한다. 임의의 100명·60분을 승인된 목표값으로 사용하지 않는다.

### 11.1 저장 정책

| 데이터 | 기본 위치 | 유지 |

브라우저 저장소는 암호화 보관함이 아니다. 앱 PIN·네이티브 보안 저장소·APK 저장 어댑터는 현재 범위에서 제외한다. JavaScript 메모리의 즉시 완전 소거도 보장하지 않는다.

### 11.2 필수 완화

- 앱 전용 origin과 기존 무료 HTTPS 호스팅 사용.
- 광고·분석 SDK·외부 실행 스크립트 금지.
- 원문·번역문·제공자 메시지는 텍스트로 렌더링.
- `eval`과 동적 코드 실행 금지.
- CSP의 네트워크 허용 대상은 실제 등록한 endpoint만 포함.
- 새 제공자는 코드 검토와 정적 재배포로 등록. 사용자 URL 입력으로 추가하지 않음.
- 키·인증 URL·헤더·제공자 오류 원문 로깅 금지.
- service worker는 명시된 정적 셸 파일만 캐시.
- 키 입력 자동완성·자동수정 최소화, 전체 보기·복사 기본 미제공.
- 키 삭제·전환 시 해당 활성 요청과 세션 종료.
- 배포 산출물·저장소·캐시의 비밀 검사.
- 배포 권한 보호와 릴리스 검토.

로컬 키 삭제와 제공자 측 키 폐기는 다르다. 유출 키는 해당 제공자 콘솔에서 폐기한다.

### 11.3 개인 키 제한

- P1 Gemini 개인 키에는 Gemini API 제한을 안내한다.
- 개인 모드는 장소 제약 없는 사용이 목적이므로 행사장 IP 제한을 권하지 않는다.
- referrer 제한은 실제 REST·Live·웹/PWA 조합을 검증한 경우에만 안내한다.
- 다른 제공자의 제한 방식은 해당 어댑터와 운영 문서에서 별도 선언한다.
- 키 제한만으로 결제 상태·무료 이용 여부를 판별하지 않는다.

### 11.4 무료 서비스 데이터 처리와 이용 가능 범위

로컬 기록 OFF는 제공자에게 데이터가 전송되지 않는다는 뜻이 아니다.

공개 출시 전 실제 제공자·이용 지역·대상·개인/공용 운영 방식에 적용되는 조건을 확인하고, 확인 날짜와 근거를 남긴다.

- 음성·텍스트 전송 및 무료 서비스 데이터 처리 안내.
- 민감한 대화 관련 조건.
- 연령 등 이용 대상 조건.
- 관리자 공용 키 운영의 허용 조건.
- 향후 다른 제공자로 전환될 때 처리 주체가 달라지는 점.

**오너 결정:** 조건 확인 전 미성년자 등을 포함해 “모두 사용 가능”이라고 홍보하지 않는다. 조건을 충족하지 못하는 범위는 미충족 요구로 남긴다.

이 결정은 약관 검증 완료를 뜻하지 않는다. 실제 공개 대상 확정은 출시 조건이다.

## 13. 웹·PWA·정적 배포

### 13.1 정적 배포

기본 배포 대상은 기존 설계의 Cloudflare Pages 무료 정적 호스팅이다. 서버 함수·새 유료 기능·도메인 구매를 요구하지 않는다.

- HTML·CSS·ES 모듈을 그대로 배포한다.
- 런타임 npm 의존성과 번들러를 도입하지 않는다.
- Node 스크립트는 검사·개발 서버·릴리스 복사에만 사용한다.
- 릴리스는 허용 목록의 정적 파일만 복사한다. 테스트·문서·원본 프로젝트·키는 제외한다.
- `_headers`에 CSP 등 보안 헤더를 선언한다.
- 실기기 마이크 시험은 HTTPS 배포 또는 신뢰된 개발 HTTPS에서 수행한다.
- 폰에서 개발 맥의 HTTP LAN 주소를 열어 마이크 지원 여부를 판정하지 않는다.
- 배포 시점의 무료 제공 조건과 헤더 적용을 확인한다.

P1부터 설치 가능한 manifest·아이콘·service worker를 포함한다. 오프라인 기록과 저장소 마이그레이션은 P3 범위다.

### 13.2 service worker와 업데이트

- 명시적 정적 셸 허용 목록만 캐시한다.
- API·인증·기록·오디오·임의 URL은 캐시하지 않는다.
- 릴리스별 URL 경로와 캐시 이름을 사용한다. 예: `releases/<releaseId>/…`.
- 릴리스 디렉터리는 덮어쓰지 않는다. HTML이 해당 릴리스의 ES 모듈만 참조한다.
- 설치 시 해당 버전 셸 전체 확보에 실패하면 새 worker 설치를 실패시킨다.
- 자동 `skipWaiting()`을 사용하지 않는다.
- 통역 종료 후 사용자가 업데이트를 선택하면 적용한다.
- 다른 탭의 통역 여부를 확인할 수 없으면 그 탭을 닫도록 안내하고 적용을 보류한다.
- 이전 탭이 참조할 수 있는 릴리스 파일과 캐시를 성급히 삭제하지 않는다.
- 잘못된 배포는 이전 릴리스를 가리키는 진입 파일로 복구한다.
- P3의 IndexedDB 변경은 이전 기록을 보존하는 방향으로 수행한다.
- 첫 방문 오프라인은 지원하지 않는다.
- 셸이 열려도 새 AI 통역에는 인터넷과 유효한 연결이 필요하다고 표시한다.

정적 복사·버전 경로 생성은 릴리스 포장 작업이며, 코드 변환이나 번들 빌드가 아니다.

- `fetch`·WebSocket·시계·오디오 경계를 주입해 오류·취소를 재현한다.
- 언어 경계·구조화 출력·무음·잘못된 응답.
- 호출 예산·늦은 응답·취소 후 재생·단일 Live 소유권.
- 제공자·키 격리·허브 전용 경로 차단.
- i18n 키 일치와 UI에서 사용하는 키의 존재.
- 원문·번역문의 HTML 실행 방지.
- 정적 캐시 허용 목록·불완전 릴리스 거부·비밀 검사.
- P2 SegmentAssembler, P3 xlsx·기록 검사를 해당 단계에 추가한다.

Node 검사는 브라우저 마이크·자동재생·설치·실제 서비스 워커 수명주기를 증명하지 않는다. 해당 항목은 브라우저 수동 시험으로 확인한다.

진단 자료는 키·발화 원문을 기본 제외한다. 실키를 CLI 인자·명령 기록·저장된 테스트 fixture에 넣지 않는다.

## 20. 제공자 추상화와 등록 계약 — 신설

### 20.1 네 능력

| 능력 | 입력 | 결과·이벤트 |
|---|---|---|
| `translate` | 텍스트, 선택적 음성, 원어·목표어 | 원문·번역문·감지 언어·상태·모델 |
| `stt` | 유한 길이 음성·선택 언어 힌트 | 전사문·감지 언어·상태·모델 |
| `live` | 스트리밍 PCM·원어·목표어 | 임시/확정 자막·오디오·중단·종료 |
| `voice` | 확정 텍스트·언어·보이스 | 오디오 청크·선택 전사·완료·오류 |

개념 계약:

```js
translate(request, context) -> Promise<TranslationResult>
stt(request, context)       -> Promise<SttResult>
live.open(request, context)-> Promise<LiveSession>
voice.open(request, context)-> Promise<VoiceSession>
```

- `context`: `turnId`, `sessionId`, `generation`, `signal`, 제한된 자격증명 참조.
- `LiveSession`: `sendAudio`, `finishInput`, `close`, 정규화 이벤트.
- `VoiceSession`: `speak`, `cancel`, `close`, 정규화 이벤트.
- 실제 키는 라우터가 선택한 경로의 인증 경계에서만 해석한다.
- 유한 요청은 성공·실패·취소·시간 초과로 종료한다.
- 스트림은 중복 종료 없이 정리되며 종료 후 이벤트는 무시한다.

공통 오디오 표준은 입력 PCM16 little-endian·mono·16kHz, 출력 PCM16 little-endian·mono·24kHz다. 다른 형식을 사용하는 제공자는 어댑터에서 변환하거나 해당 경로를 미지원으로 선언한다.

### 20.2 제공자 등록 정보

```text
id / label
browserDirect: true | false
capabilities:
  translate / stt / live / voice:
    implementation: ready | planned | unsupported
    transports: direct[] 또는 hub[]에 해당하는 허용 경로
    inputFormats / outputFormats
    models / voices
credentialPolicy:
  directPersonal / directShared / hubManaged
quotaPolicy:
  scope / normalizeError
fallbackPolicy:
  능력별 후보·허용 오류·전환 조건
endpoints:
  코드에 고정된 HTTPS/WSS 허용 목록
terms:
  안내 식별자·검토 상태·검토일
```

`browserDirect: false`는 제공자 전체의 강제 차단이다. `true`여도 능력별 경로에서 더 좁게 제한할 수 있다.

등록 선언은 기술·운영 정책이고, 현재 키·브라우저·네트워크의 연결 성공 증거는 아니다.

### 20.3 P1 능력 표

| 제공자·능력 | 직접 호출 선언 | P1 구현 | 표시 |
|---|---|---|---|
| Gemini `translate` | 가능 | 텍스트·WAV 결합 번역 | 미검사 → 검사 결과 |
| Gemini `stt` | 가능 | WAV 전사 | 미검사 → 검사 결과 |
| Gemini `voice` | 가능 | Live 목소리 | 미검사 → 검사 결과 |
| Gemini `live` | 가능 | P2 예정 | 준비 중 |
| 향후 직접 호출 불가 제공자 | 불가 | 미구현 | 현장 허브 필요 |
| OpenAI 등 미등록 제공자 | 미판정 | 미구현 | 제품 선택기에 노출하지 않음 |

P1에서 실제 두 번째 제공자를 추가하지 않는다. 테스트 fixture로 직접 허용·허브 전용·미지원 제공자를 등록해 구조를 검증한다.

### 20.4 라우팅·키·폴백

1. 요청 능력과 구현 상태를 확인한다.
2. 선택 제공자와 허용 transport를 확인한다.
3. 해당 제공자·키 출처의 자격증명만 선택한다.
4. 작업 공통 예산으로 호출한다.
5. 제공자 오류를 정규화한다.
6. 등록된 조건의 폴백만 적용한다.

허브 전용 경로에 허브가 없으면 `HUB_REQUIRED`로 종료한다. 브라우저 직접 호출로 우회하지 않는다.

P1 자동 폴백은 Gemini 내부의 검증된 모델과 기기 음성까지다. 제공자·개인/공용 키 출처를 자동으로 바꾸지 않는다.

향후 제공자 간 폴백은 사용자가 데이터 처리 주체와 사용할 키를 명시적으로 선택한 정책에 한해서만 등록한다. 한도 우회·안전 차단 우회·미확인 유료 전환은 폴백 사유가 아니다.

# P1 구현 과제 목록

각 과제는 **Astra의 한 번의 `codex exec --full-auto` 실행 단위**다. 실행당 아래 파일 3~6개만 신규·수정하고 의존 과제의 계약을 사용한다. 파일 수에는 테스트와 문서도 포함한다.

cd ~/jarvis2/interp-app/

아래 명령은 **구현 후 실행할 완료 확인 명령**이며, 이 문서 작성 중 실행한 결과가 아니다. Node 명령은 Node 24를 전제로 한다. 브라우저 수동 시험이 필요한 과제는 그 결과도 완료 기록에 포함한다.

# 1라운드에서 스스로 고친 것

| v0.5에 남아 있던 문제 | v0.6에서 확정한 표현·처리 |
|---|---|
| 보안 경계가 계속 오너 승인 대기로 남음 | 정책 승인 완료. 실제 기능·행사별 제한 시험만 남음 |
| P2가 “실제 설교 길이 60분”으로 고정됨 | 실제 길이는 P2에서 확인. 그 전체 길이로 시험 |
| APK·스토어가 후속 기본 경로로 남음 | 현재 구현·배포·지원표에서 제거 |
| PWA만 배포하면서 설치 기능은 P3까지 없음 | 최소 설치·셸·업데이트 안전성을 P1로 이동 |
| Gemini에 묶인 UI·키·오류 구조 | 네 능력과 제공자·transport 계약으로 분리 |
| STT 구현이 없는데 PTT→WAV 번역이 완성 경로처럼 보임 | 기존 파일은 텍스트 전용임을 확인. 결합 음성 번역과 독립 STT를 명시적 신규 구현으로 지정 |
| 원본 번역기의 여러 모델·설정 재시도와 총 3회 정책 충돌 | 숨은 재시도 제거, 모든 단계의 공통 예산 적용 |
| Live 목소리 코드를 바로 브라우저로 가져올 수 있는 인상 | Node `ws`·Electron IPC 제거를 별도 이식 과제로 지정 |
| 기존 목소리 지연이 실제 스피커 첫소리처럼 읽힘 | 첫 수신·예약 재생·실제 첫소리를 분리 측정 |
| 부분 음성 실패 후 폴백이 중복 읽기를 만들 수 있음 | 부분 재생 뒤 자동 전체 재독 금지 |
| provider 등록을 곧 지원 완료로 오해할 수 있음 | 구현 상태·접속 경로·연결 검사 상태 분리 |
| 서비스 워커 업데이트 보류만으로 버전 혼합 방지가 불명확 | 불변 릴리스 경로·완전 설치·다중 탭 적용 조건 명시 |
| 키 검사·마이크 검사가 모든 사용자의 필수 진입 단계 | 텍스트는 마이크 없이 시작, 음성 검사는 사용자 동작으로 수행 |
| “모두”와 이용 조건의 충돌이 오너 미결정으로 남음 | 대상 확대 홍보 보류는 확정. 실제 약관·대상 검증은 계속 출시 조건 |
| 자동 테스트 통과와 실기기 출시 합격이 섞임 | 구현 완료·개인·PWA·공용·행사 규모 검증을 각각 판정 |

파일과 코드는 수정하지 않았다.
