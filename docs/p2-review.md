# P2-21 통합·개인정보 회귀 검수

2026-09-06, Node v24.18.0. `design-p2.md` §7.3·8.4~8.6·9·10·17 및 `design-v0.6.md` §20·11·12와 편입된 v0.5 §12를 기준으로 검사했다. P1-20b 검수와 P1 구현 보고, P2-18·19·20 인계 사항을 대조했다.

## 변경 범위

- `tests/p2-integration.test.mjs`: 실제 앱 구성 경계의 회귀 10개 신규.
- `tests/fixtures/p2-scenarios.mjs`: 기존 P1 브라우저 fixture를 재사용하는 구성 도우미 신규.

- `docs/p2-review.md`: 이 보고서 신규.

제품 파일·사전·기존 테스트 단언은 변경하지 않았다. 외부 패키지·빌드 도구·커밋·배포를 추가하지 않았다. 지정된 원본 translate/live/xlsx 및 음성 처리 심벌과 기존 이식 경계를 확인했으며 새 원본 코드를 이식하지 않았다. fixture 상단에 신규 조합 코드임을 명시했다.

## 구성과 검증 증거

`startApp`으로 실제 셸·설정·작업 소유권·순차 엔진·직접 엔진·허브 엔진·라우터·Gemini 어댑터·세션 관리자·자막 조립기·PCM 재생기·기기 TTS·PWA를 구성한다. 엔진의 성공 결과를 모의로 반환하지 않는다. 브라우저 DOM·WebSocket·REST·마이크·AudioContext·speechSynthesis·저장소·서비스 워커와 시간 진행만 모의다. 허브 주소는 구성 인자로 주입한 테스트 전용 등록이며 제품 등록을 변경하지 않는다.

| 사례 | 관측·단언 |
|---|---|
| 순차 목소리 → 직접 → 허브 → 순차 | 진행 중 PCM 취소, 이전 물리 소켓 종료, 마이크 종료, 허브 TTS 취소, 마지막 순차 REST 완료 |
| goAway·503·원격 단절 | 이전 연결 종료 후 제한 대기·새 setup, 복구 중 진단·순차·업데이트 차단, 이전 음성 재전송 없음, 새 마이크 프레임만 전송 |
| 미확정 자막 종료 | 복구 전 남은 부분 자막은 정상 final이 아닌 interrupted |
| 원인 불명 429 | UNKNOWN_429로 실패, 모델 순환·REST 자동 폴백·추가 연결 없음 |
| 구조화된 분당 429 | RetryInfo의 9초가 앱 지터보다 우선, 8초까지 새 연결 없음, 중지 후 대기 취소 |
| PCM overflow | 4초 청크 후 5초 추가 시 따라잡기, 기존 소스 정지, 자막은 유지, 자막 확정만으로 음성 재개하지 않음, 제공자 턴 경계 뒤 재개 |
| 허브 중복·revision·재접속 | 참가 직후 최근 자막 무음, 확정 후 수정은 화면만 갱신, 재접속은 음소거, 이미 읽은 구간은 재낭독하지 않음, 새 구간만 낭독 |
| 허브 방송 종료 | cast.stopped 뒤 소켓·작업 종료, 자동 재참가 없음 |
| 키 삭제·업데이트 경쟁 | close를 지연시킨 동안 업데이트 적용·reload·새 작업 차단, 늦은 오디오 무시, 물리 종료 뒤 보류 reload 1회 |
| 소켓 종료 확인 실패 | deadline 후 실패하지만 전역 lease 점유 유지, 새 연결·업데이트 계속 차단 |

모든 새 소켓 생성 시 CONNECTING·OPEN·CLOSING을 합산해 최대 1개를 확인한다. 직접·허브 전환 사례에서는 허브까지 합산하는 더 엄격한 관측을 사용한다. 취소 후 늦은 PCM·TTS 완료 콜백·허브 자막으로 추가된 재생은 0이며, 같은 확정 구간의 자동 중복 낭독은 0이다. PCM 실제 스피커 출력이 아닌 예약·stop 호출과 TTS 요청 횟수의 검증이다.

## 개인정보 경계

직접 오류의 message·details와 허브 fatal.detail·close reason에 합성 비밀 표식을 주입했다. 앱 URL·history·DOM의 텍스트/속성/입력값·localStorage·상태 구독 이력·진단·PWA·REST URL/본문·소켓 송신 프레임·정규화 오류 객체·console 기록에서 비밀 없음이 통과했다. 허브 방 코드도 같은 관측값에 남지 않는다. 허브 자막의 HTML 형태 문자열은 텍스트로 표시되며 IMG 노드를 만들지 않는다. 키 없는 허브 참가에서 마이크·제공자 REST 호출은 0이다.

설계에 명시된 전달 경계는 별도로 정확한 값을 확인한다. Gemini Live 생성자의 인증 URL에는 키가, 허브 참가 소켓 URL에는 방 코드가 필요하다. 기존 P1은 REST 인증 헤더와 사용자가 저장에 동의한 개인 키 슬롯도 검사한다. 따라서 모든 네트워크 URL·모든 선택 저장에서 키가 없다고 주장하지 않는다. 새 검사는 기본 메모리 보관을 사용하며 저장소는 비어 있다. 테스트 운반 기록에만 이 값을 보관하고 실제 키는 사용하지 않았다.

기존 개인정보 검사의 출하 소스·CSP·릴리스 허용 목록·stage/check-release·비밀 패턴 검사도 그대로 전체 실행에 포함된다.

## 설계 적용과 남은 경계

설계 변경·선행 테스트 기대값 변경·선행 모듈 대체 인터페이스는 없다. 처음 실패했던 테스트의 방 코드 형식, 허브 화면 선택, 송신 펌프의 0ms 타이머, 지터 범위를 기존 제품 계약에 맞췄다. 지터는 실제 공통 정책의 1,000~1,250ms 범위를 허용한다.

소켓 종료 timeout은 전역 점유를 의도적으로 유지한다. 이 검사는 파일 마지막에서 수행하며 전체 실행은 기존 Node 테스트의 파일별 프로세스 격리를 사용한다. 물리 close가 뒤늦게 도착했다고 timeout으로 실패한 lease가 자동 회복된다고 주장하지 않는다. 향후 사례를 이 검사 뒤에 추가하거나 프로세스 격리를 끄지 않아야 한다.

P2-18 인계에 있던 운영 지표 수집 및 허브 진단 상태의 `main.js` 연결 누락은 이번 허용 파일 범위 밖이다. 기존 주입 인터페이스를 제품에 연결하지 않았으며 운영 실측 완료로 표시하지 않는다. 이 보고서의 카운터는 테스트 fixture의 관측이다. 후속 작업에서 허용 범위를 정해 실제 수집·진단 화면 연결을 검증해야 한다.

제품 허브 등록 목록은 현재 비어 있다. 테스트용 주입 성공은 운영 허브 등록·CSP 배포 성공 증거가 아니다. P2-22의 규모 도구, P2-23의 Android/iPhone·Safari 최초 로드·실키·PWA·공용 회선 제한, P2-24의 목표 규모·전체 예배 시험은 별도로 남는다. 실제 번역 품질·실청취 지연·OS 오디오 취소·배터리·발열·서버 느린 청중 격리·최대 동시 인원은 이번에 측정하지 않았다.
